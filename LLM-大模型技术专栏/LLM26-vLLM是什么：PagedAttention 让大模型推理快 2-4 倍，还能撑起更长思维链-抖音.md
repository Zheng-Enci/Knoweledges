## P01 · 封面

> 卡片职责：三秒钩子，先给结论再给数字

- 大标题：vLLM 快 2-4 倍却不提智商
- 副标题：它到底改了什么
- 核心数字：显存浪费 60%–80% → 4% 以下

## P02 · 一句话定性

> 卡片职责：先把 vLLM 放进正确的位置，避免后面全跑偏

- vLLM 是开源的推理服务引擎，不是新模型
- 它由 UC Berkeley Sky Computing Lab 发起
- 对外是 OpenAI 兼容接口，换个 base_url 就能跑
- 对内只做三件事：调度、管显存、拼 batch
- 训练是一次性的，推理是长期的，它只管后半段

## P03 · 两个推理

> 卡片职责：拆开「推理」这个词的双重含义，这是全篇的钥匙

- 中文把 inference 和 reasoning 都译成「推理」
- inference 指把输入 token 变成输出 token 的一次前向
- reasoning 指模型解决多步问题的能力
- vLLM 改得动前者，改不动后者
- 它不碰权重，也不会因为用了它就多想几步

- 表格：维度 | inference | reasoning
- 表格：指的是什么 | 一次前向计算 | 多步问题能力
- 表格：能不能被改 | 能，改速度成本 | 不能
- 表格：衡量指标 | throughput、TTFT | 准确率、pass@k

## P04 · 显存去哪了

> 卡片职责：解释旧系统为什么把显存吃光

- 自回归生成时，前面 token 的 K/V 不变，缓存最省
- 但这块 KV Cache 大小动态且不可预知
- 旧系统按最长长度预分配，内部碎片能空掉 80%
- 每条请求要连续显存，释放后的空洞填不进去
- 8×A100-80GB 跑 LLaMA-13B，约 300 GB 被空槽占着
- 显存空着 batch 就开不大，算力跟着闲置

## P05 · 分页注意力

> 卡片职责：给出核心机制，配一个后厨比喻

- 把 KV Cache 切成固定 block，默认 16 token 一块
- 每条请求一张 block table，记逻辑块映射物理块
- 注意力 kernel 按表去散落的物理块里取 K/V
- 外部碎片直接消失，浪费率降到 4% 以下
- 🍜 比喻：不是换米其林大厨，是把后厨动线重排
- 灶台不空等配菜，八锅同开火却共用一口汤锅

## P06 · 连续批处理

> 卡片职责：解释 GPU 为什么从空转变满转

- 静态批处理：最长那条不结束，整批都得等
- 连续批处理把调度粒度缩到「一次前向」
- 每跑一步就换人，结束的踢出、排队的进来
- Anyscale 在 Llama-13B 上实测最高 23 倍吞吐
- 长 prompt 会卡住所有人，于是切块与 decode 合批
- 🚌 比喻：包车人齐才走，公交每站都停

## P07 · 前缀缓存

> 卡片职责：讲清一项只省 prefill 的优化

- 线上流量前缀高度重复：系统提示词、few-shot 示例
- 每个 block 按哈希比对，命中的直接复用不重算
- 只缓存完整 block，零头不算
- 只省 prefill，不省生成阶段
- 差一个字符就整块失效，时间戳得挪出前缀

## P08 · 变好的真相

> 卡片职责：回答「为什么感觉推理性变好」，给出四层因果

- 第一层：上下文变长，能塞更多示例与文档
- 第二层：多路采样变便宜，这是最关键的一层
- 第三层：显存省下来，batch 开更大，成本继续降
- 第四层：长输出不再被卡死，思维链才敢放开
- 四层是间接因果，中间隔着「成本」这一环
- 💡 vLLM 不提高智商，它降低「多想几遍」的价格

## P09 · 投票数据

> 卡片职责：用一组可复算的数字证明多采样真能提准确率

- Self-Consistency 的做法：多采几条思维链，对答案投票
- LaMDA-137B 上 MultiArith 提升 23.9 个百分点
- SVAMP 提升 14.4 个百分点，其余任务约 +10
- PaLM-540B 上 GSM8K 从 56.5% 提到 74.4%
- 成本是线性的：采 8 条就付 8 条的钱
- vLLM 把单条压到 1/2 到 1/4，同预算多采 2 到 4 倍

## P10 · 三个误解

> 卡片职责：扫掉三个最常见的错误认知

- 误解一：vLLM 能提升能力。同权重同 prompt 输出一致
- 误解二：它只是快一点的 transformers，低并发下可能更慢
- 误解三：量化能白拿性能，小 batch 下首 token 反而更慢
- 投机解码、PD 分离、TP/PP 都只改跑多快，不改输出分布

## P11 · 什么时候用

> 卡片职责：末页只给判据，不复述全文

- 瓶颈在 GPU 利用率与单位 token 成本时，值得上
- 瓶颈在模型本身答不对时，先换模型、补示例
- 想提准确率又嫌贵，先用自洽性采样，让它把账压下来
- 低并发、短序列、单请求，收益有限甚至略亏
