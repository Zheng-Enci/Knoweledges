## P01 · 封面

> 卡片职责：抛钩子，点出「同一个模型，跑起来却像两个人」的反差

- 大标题：**同一个模型**，本地怎么变笨了
- 副标题：不是模型的问题，是**偷偷降了精度**
- 核心数字：INT4 让数学题准确率**掉 9%–18%**

## P02 · 模型权重其实一模一样

> 卡片职责：先破误解——权重是同一套，差别在怎么跑

- 很多人以为厂商把本地模型阉割了，**其实权重完全一样**
- 差的是模型在本地被「**怎么喂**」和「**怎么跑**」
- 同一套菜谱，**铁锅**和塑料锅炒出来是两个味
- 排查顺序：先看精度，再看模板，最后调参数

## P03 · 量化是头号元凶

> 卡片职责：讲清量化精度损失是最大差别来源

- 云端用 **bf16/FP8** 高精度跑，几乎零损失
- 本地为省显存几乎都会**量化**，压到 8 位、4 位
- **INT8** 基本无损，MMLU 还能保住 **99.2%**
- **INT4** 一压就露馅，数学推理掉 **9%–18%**

## P04 · 量化专伤「会算的数」

> 卡片职责：解释为什么数学代码最受伤，常识还行

- 量化对**纯背诵**伤害小，对**会算的数**伤害大
- 所以你问数学、写代码觉得变笨了，问常识又觉得还行
- **MMLU**（事实知识）只掉 **1%–3%**
- **GSM8K**（数学推理）却掉 **9%–18%**，反差最大

## P05 · 长上下文更脆

> 卡片职责：补充量化在长文本下会进一步恶化

- 4-bit 量化在 context 变长时**逐渐恶化**
- 换种语言输入，掉得更明显
- **8-bit** 则基本保持，长文也稳
- 所以本地一问长文就露馅，云端却没事

## P06 · 聊天模板用错也变笨

> 卡片职责：点出第二层原因——模板错位

- 每个模型都有自己的 **chat template**「语法书」
- 它规定 system / user / assistant 的角色边界
- 模板错了，模型把对话当**一坨纯文本**，答非所问
- 对齐云端的关键一步，就是用**官方模板**加载

## P07 · 采样参数决定气质

> 卡片职责：讲清第三层原因——温度、核采样

- 精度决定模型多聪明，**采样参数**决定往哪飘
- **temperature** 越高越放飞，越低越保守
- 云端常默认 0.7，本地默认 1.0 就变「胡说」
- 想对齐，就把两端 **temp / top_p / max_tokens** 设一致

## P08 · 一段能跑的对答案代码

> 卡片职责：给可直接跑的对照实验，让读者自己验证

- 本地 Ollama 和云端 API 都当 **OpenAI 兼容接口**调
- 用**完全相同的 prompt** 和采样参数，只改 base_url
- 差别大 → 大概率是本地做了激进量化
- 把 **temperature** 调到 0.8，还能看到输出「飘」起来

## P09 · 什么时候追得上

> 卡片职责：给判据——哪些 task 本地能对齐，哪些永远追不上

- 事实问答、翻译、改写：**INT8 就能对齐**云端
- 数学推理、长文、代码：**INT4 永远追不上** bf16
- 选型口诀：本地图便宜离线，云端图精度稳定
- 别为「追上云端」盲目堆显卡，先问自己要哪头

## P10 · 一句话总结

> 卡片职责：判据式结论 + 互动钩子，点题收尾

- 本地变笨，先查**精度、模板、参数、截断**四层
- 要数学代码长文，别指望 INT4 追平云端 bf16
- 你碰过「本地跑同一模型明显变笨」吗？
- **A 碰过 B 没碰到**，评论区聊聊
