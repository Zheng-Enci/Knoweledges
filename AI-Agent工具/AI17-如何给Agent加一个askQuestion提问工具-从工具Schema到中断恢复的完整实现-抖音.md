## P01 · 封面

> 卡片职责：抛钩子 + 定锚主题，点破「askQuestion 提问工具」核心名词

- **怎么给 Agent 加提问工具？**
- 让 Agent 停下来问你，而不是瞎猜硬动手
- **4 个**必填字段，定义好提问工具 Schema

## P02 · 为什么 Agent 需要「会提问」

> 卡片职责：讲提问工具的价值，建立必要性

- Agent 失败一大原因是**信息不足还硬猜**：说订票没问去哪、说优化没问目标。
- 加提问工具的价值：把「未知」变已知，把「自作主张」变「用户确认」。
- 关键节点问一句，用户才敢把事交给 Agent——像手术前的知情同意。
- 不问就动手，出了事往往无法挽回 ⚠️。

## P03 · 关键认知：工具调用即中断

> 卡片职责：讲核心机制，区分普通工具与提问工具

- askQuestion 和普通工具的执行方式完全不同。
- 普通工具：调用后执行逻辑、毫秒级返回结果。
- **提问工具**：调用后**暂停执行**，等用户输入，可能等几秒到几小时。
- 所以它本质是个**中断（interrupt）**，不是普通函数调用 ⚡。

## P04 · 中断恢复六步：暂停再接着跑

> 卡片职责：讲完整链路，给骨架

- ① Agent 决定调用 ask 工具 → ② 执行流暂停，把状态存下来。
- ③ 问题抛到前端弹窗 → ④ 用户回答。
- ⑤ 答案包装成这次工具调用的结果，回填给 Agent。
- ⑥ Agent 从暂停点继续跑——像游戏从存档点接着玩 🎮。

## P05 · Schema 设计：问题、选项、多选

> 卡片职责：讲工具定义，给 4 个关键字段

- **question**：问题要具体，别问「你想咋办」，要问「两套方案选哪个」。
- **options**：必须有 2–4 个明确选项，每个带一句后果说明。
- **multi_select**：允许多选还是单选，按场景定。
- 关键：选项别是模糊的「是/否」，要带后果，用户一看就能选 📋。

## P06 · 状态必须能序列化

> 卡片职责：讲技术难点，强调存档能力

- 用户可能要很久才回答，中途进程可能重启——状态不能只存内存。
- 暂停时要把对话历史、任务进度、待回复的 tool_call_id 全部序列化。
- 恢复时答案必须**绑定原来的 tool_call_id**，Agent 才知道它属于哪次提问。
- 类比 🎭：像在线问卷，填一半关掉，下次从进度继续，因为每笔都存了档 💾。

## P07 · 框架怎么做：LangGraph 与 OpenAI SDK

> 卡片职责：讲成熟框架，避免重复造轮子

- **LangGraph**：图节点内 `interrupt()` 暂停，用 `Command` 携带答案恢复。
- **OpenAI Agents SDK**：工具声明需要审批，`RunState` 序列化暂停的运行。
- **Agno**：`UserFeedbackTools` 提供 `ask_user`，结构化问题加选项。
- 共同点：都是「工具触发 → 中断 → 恢复」三段式，状态都可序列化 🔧。

## P08 · 提问规范：什么时候问怎么问

> 卡片职责：讲策略，避免 Agent 变十万个为什么

- **该问**：必要参数缺失、关键决策点、高危动作（删除/支付/发送）。
- **不该问**：能自己推断的、无关紧要的细节、同一件事重复确认。
- **怎么问**：一次一问、给推荐项、选项带后果说明。
- 本质：**猜错的代价 > 打扰的成本，才值得问** ⚖️。

## P09 · 三种反模式：问太多问太泛问了不接

> 卡片职责：讲翻车方式，给避坑清单

- **问太多**：每个小决定都问，用户被烦跑 → 只问高危/缺失/关键决策。
- **问太泛**：问「你想怎么办」，用户答「你看着办」→ 给具体选项。
- **问了不接**：弹窗后答案没回填，Agent 卡死或重跑 → 接上 tool result 回填。
- 第三种最致命：问得再好，链路断了等于白问 🚨。

## P10 · 判断收尾 + 互动钩子

> 卡片职责：给判据式结论 + 唯一一句互动钩子

- 判断标准：**猜错的代价是否大于打扰用户一次的成本**——大于，就值得问。
- 该加：信息常缺失、有高危动作、多种合理方案需拍板的任务。
- 不必加：边界清晰、信息每次给全、无高危操作的任务。
- 一句话收束：**askQuestion 不是普通工具，是让 Agent 停下来问人的开关**——答完再继续。
