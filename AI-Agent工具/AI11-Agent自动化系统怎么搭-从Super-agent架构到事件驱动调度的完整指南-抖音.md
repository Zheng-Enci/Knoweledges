## P01 · 封面

> 卡片职责：抛钩子 + 定锚主题，点破「Agent 自动化」核心名词

- **Agent自动化系统到底怎么搭？**
- 副标题：AI 当主管、Agent 当工人，你只做关键决策
- 核心数字：**3 到 5 个**活跃会话，就是人的注意力上限

## P02 · 你的注意力就是多任务的天花板

> 卡片职责：引出注意力瓶颈，讲清为什么聊天式用法不够

- DeepSeek 在 Super-agent 文章开篇点破：**单任务上限看模型能力**，**多任务上限看人注意力**。
- 普通人同时只能跟进 **3 到 5 个**活跃会话，你开再多窗口，盯得过来的也就这几个。
- 聊天式用法的问题：**所有任务起点都是你**，你不打开窗口，什么都不会发生。
- 所以真正卡住你的从来不是模型，是你只有一对眼睛 👀。

## P03 · 六百年前朱元璋也栽在同一个坑里

> 卡片职责：用历史类比强化注意力瓶颈，制造记忆点

- 1380 年朱元璋废掉丞相，六部直接对皇帝负责，天下大事全堆到他一人桌上。
- 洪武十七年 8 天送来 **1660 件**奏札、要处理的事 **3000 多件**，一天平均 **400 多件事**。
- 勤快如他也绷不住，当场说：「朕一人处此多务，岂能一一周遍」——一个人怎么顾得过来。
- 六百年后换成 AI 社会，**递奏折的不再是六部九卿，而是一群 Agent**。

## P04 · 解法：让 Router 当主管，Worker 当工人

> 卡片职责：介绍 Super-agent 双层架构，点破分工本质

- DeepSeek 给出一套 Router / Worker 双层架构，本质是把「好团队」数字化。
- **Router（路由器）**：持续在线的全局协调节点，接消息、分任务、维护全局上下文，像 AI 主管。
- **Worker（工作器）**：一批相互隔离的会话，并发执行问题复现、代码审查、功能开发，做完向 Router 汇报。
- 好处是上下文互不污染、任务真并行，速度不再受你的眼睛限制 🚀。

## P05 · 核心关键：用事件代替指令

> 卡片职责：讲事件驱动，这是从「等命令」到「主动干活」的分水岭

- 双层架构解决分工，**事件驱动（event-driven）** 解决谁来发起任务——答案是不用人发起。
- 定时任务、Webhook、告警、CI 结果、GitHub 评论，任何信号都能触发一个 Agent 干活。
- 告警来了 → Agent 自动查日志 → 定位 bug → 直接修复 → 提交 PR，全程不用你出现。
- 像好团队一样：**大臣能自己处理的不上报，拿不准的才请你拍板** 🎭。

## P06 · 不是所有信号都触发，两级过滤挡噪音

> 卡片职责：讲两级过滤与订阅直通，说明怎么防止系统被消息淹没

- 所有信号都触发 Agent 是灾难，DeepSeek 用**两级过滤**挡住噪音。
- 第一级 Fast Path（快速路径）：程序规则按来源、关键词筛，**快且免费**，不耗模型。
- 第二级 Slow Path（慢速路径）：剩下需要语义判断的才交给大模型，**灵活但贵**。
- 同话题后续事件直接推给订阅它的 Worker，不再绕 Router——主管不当传声筒 📢。

## P07 · 再加一个 Watchdog 防跑偏

> 卡片职责：讲外部控制回路，保证自主干活不失控

- 让 Agent 自主干活，最大风险是**跑偏了没人知道**，DeepSeek 加了独立 Watchdog 会话。
- 它不干活，专门监控两类问题：基础设施故障（接口报错）和方向问题（没进展、偏离目标）。
- 发现异常就主动介入：终止原地打转的 Worker，或纠正执行方向。
- 对应到个人就是一条规则：**定期检查 Worker 实质产出**，没有就停掉重派 🔍。

## P08 · 普通人落地：一个事件中台就够

> 卡片职责：讲个人可落地的简化版架构，给出事件中台三件事

- 个人不用复刻整个开源原型，一个**事件中台（event middleware）** 就够，核心三件事。
- 第一定义事件：cron 定时、告警、消息、代码事件，统统归纳成统一格式。
- 第二统一路由：中台统一接事件、按规则叫醒对应 Agent，**新增事件只需加一条规则**。
- 第三人工决策：Agent 产出整理成卡片推到飞书，你只在卡片上点「同意 / 驳回」✅。

## P09 · 这一年实测：一个人运转十几个 Agent

> 卡片职责：给出实战结果数字，讲清注意力从 3-5 拓宽到十几个的收益

- 按这套事件中台实践近一年，一个人同时运转了**十几个自动化 Agent**，不用逐个窗口盯。
- 运维告警、系统日报、浏览器操控、到期复查，各归各的 Agent 并行推进。
- 注意力瓶颈从 **3 到 5 个**会话拓宽到十几个 Agent，瓶颈不是模型、不是工人，而是人的注意力。
- 这就是把「领导力」落进系统：**你只做最关键的判断**，其余交给系统自己跑 ⚡。

## P10 · 判断收尾 + 互动钩子

> 卡片职责：给判据式结论 + 唯一一句互动钩子

- 判断标准：有「**持续发生、值得自动处理**」的事件流（告警、日报、CI 修复）就值得上这套架构。
- 只是偶尔用 Agent 处理单个任务，就别搭中台，聊天式反而更快——**不要过度设计**。
- 一句话点透：Agent 自动化的终点，是让系统像好团队一样自行推进，而不是等你拉一下才动一下。
