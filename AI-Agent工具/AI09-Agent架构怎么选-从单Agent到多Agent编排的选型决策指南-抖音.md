## P01 · 封面

> 卡片职责：抛钩子，标题 + 核心数字

- 大标题：**Agent架构别乱选**，先看这一点
- 副标题：多 Agent 不是更高级，是更烧钱
- 核心数字：**2~10 倍** token 成本

## P02 · 固定形状 vs 运行时形状

> 卡片职责：讲清两个根本概念，选型的基石

- Workflow 是**固定形状**：步骤顺序提前定死，每次跑都稳定
- Agent 是**运行时形状**：给目标加工具箱，模型现场决定怎么走
- 判断口诀：流程能固定就用 **workflow**，不能固定才用 agent

## P03 · workflow 优先，agent 兜底

> 卡片职责：给核心原则，Anthropic 官方建议

- 别一上来就问「单 Agent 还是多 Agent」——**问反了**
- Anthropic 建议：**始终优先实现 workflow**，只在真正需要时用 agent
- 理由：workflow 给生产 app 需要的**可靠性与可预测性**

## P04 · 单 Agent 够用的 3 条判据

> 卡片职责：给单 Agent 的适用边界，避免过度设计

- 步骤数可预估，大概 **3~5 步**能闭环
- 工具少而相关，**3~5 个**以内别贪多
- 任务串行推进，**不需要并行**拆块

## P05 · 多 Agent 只有两种值

> 卡片职责：纠正「多 Agent 更高级」的误解

- **真并行**：任务能拆成互不依赖的子块，同时跑更快
- **生成+校验**：一个写、一个以全新视角审，提升最大
- 顺序推理任务上多 Agent **普遍退化**——别硬上

## P06 · 顺序链路失败率乘法累积

> 卡片职责：给多 Agent 的数学依据，制造对比

- 单步可靠 **95%**，链 5 步只剩 **77.4%**
- 链 10 步掉到 **59.9%**，越接越不稳
- 单步可靠 **90%**，10 步只剩 **34.9%**——这就是硬伤

## P07 · 框架选型一句话

> 卡片职责：给四家框架的速选结论

- 严格执行控制选 **LangGraph**，state 管理最稳
- 快速搭原型选 **CrewAI**，上手最快
- **AutoGen** 已进维护模式，新项目别用
- 你为「高级感」硬上过多 Agent 吗？A 上过 B 没上

## P08 · 判据式结论

> 卡片职责：末页给判据 + 互动钩子

- 能固定就用 workflow，不能并行也没新视角就 **别上多 Agent**
- 多 Agent 烧 **2~10 倍** token，常常只换 **±4%** 提升
- 你被「多 Agent 更高级」坑过吗？A 踩过 B 没踩过
