## P01 · 封面

> 卡片职责：抛钩子 + 定锚主题，点破「GUI Agent 打转」核心名词

- **GUI Agent 打转死循环怎么解决？**
- 防打转失效的四个根因 + 一套根治方案
- **3 轮**画面无变化就该止损，别等 8 次真失败

## P02 · 打转的本质：感知不到画面没变

> 卡片职责：讲清打转机制，立起「感知盲区」根因

- GUI Agent 循环：截图 → 决定动作 → 执行 → 再截图 → 判断画面变没变。
- 打转发生在判断这步：模型截图后**看到的还是同一个画面**，但不知道「画面没变」。
- 它没有「拿上一张截图对比」的能力，于是推断「要多点几下 / 换个方式点」。
- 类比 🎭：像电话没人接你一直重拨——电话没坏，是对方没听到 🔍。

## P03 · 根因一：动作全「机械成功」止损失效

> 卡片职责：讲第一个失效点，点出「失败定义错」

- 你的失败止损设了 `FAIL_THRESHOLD=8`，但**它根本没机会触发**。
- 模型反复点图标、按 win、微移鼠标，这些动作都返回 **ok=True**（鼠标真动了、键真按了）。
- 阈值只统计「真失败」（ok=False），而打转的动作全是成功 → 8 次真失败永远到不了。
- 教训：**把「成功」定义为「动作执行了」是错的**，要改成「画面前进了」⚡。

## P04 · 根因二：防打转被「微调参数」绕过

> 卡片职责：讲第二个失效点，「完全相同」判据太严

- 你的防打转要求「连续 3 次**完全相同**动作」，但模型每次都换着说。
- target 描述不一样：「左侧绿色图标」「最右侧圆形图标」「气泡」。
- 坐标也都微偏：都在 x≈1205 / y≈1056 附近，但每次数字略有不同。
- 所以「完全相同」匹配不上，提示一直没发——判据太严 🎯。

## P05 · 根因三：缺画面对比，根因四：思考档太低

> 卡片职责：讲后两个根因，合并收束

- **根因三**：模型没有「画面对比」能力，感知不到「我这个动作对画面毫无影响」。
- 它以为「多试几次就行」，其实画面根本不动——这是最深的感知盲区。
- **根因四**：低思考档（low）削弱元认知，模型不会停下来反思「我是不是在打转」。
- 解法提示：排查时临时调高思考档，看它能否自己停下 🤔。

## P06 · 核心解法：成功 = 画面前进了

> 卡片职责：给核心转向，改变判定标准

- 四个根因指向同一个解法：**改变「成功」的判定标准**。
- 旧的：动作执行成功（ok=True）= 成功 → 打转全是成功，检测失效。
- 新的：**动作后画面前进了才算成功** → 画面没变就是「无效动作」。
- 这个转向让防打转从「碰运气」变「确定性检测」——画面不动就抓 ⚡。

## P07 · 落地一：画面哈希检测「无变化轮」

> 卡片职责：讲第一板斧，哈希判断画面是否变

- 每轮截图算一个**哈希值**：压缩到小尺寸再哈希，相同哈希 = 画面没变。
- 存上一轮哈希和这轮对比，维护「无变化轮数」计数器。
- 画面连续 **3 轮**没变，就触发「疑似打转」提示 / 止损。
- 类比 🎭：像给每帧画面拍指纹照，两帧指纹一样说明画面根本没动 📸。

## P08 · 落地二：wait-screenshot-verify 三步

> 卡片职责：讲第二板斧，让验证准确

- 每个动作后加「等待-截图-验证」三步，而不是动作完直接看。
- **Wait 等待**：动作后先等稳定时间，让页面加载、动画结束，别截到中间态。
- **Screenshot 截图 + Verify 验证**：和动作前对比，画面变了吗？
- 验证从「动作是否执行」挪到「画面是否变化」，这是防打转的关键 📌。

## P09 · 落地三：坐标漂移 + 迭代上限兜底

> 卡片职责：讲第三板斧，给硬性保险

- **坐标漂移检测**：多个动作坐标高度接近（都在 x≈1205 / y≈1056）且画面没变 → 疑似打转。
- 这能抓住「换着说法点同一处」的循环，比「动作文本相同」更准。
- **迭代上限**：循环外层设 max_iterations，到达强制停止——像安全带兜底。
- 三层叠加：哈希抓「画面没变」→ wait-verify 让验证准 → 迭代上限兜底 🛡️。

## P10 · 判断收尾 + 互动钩子

> 卡片职责：给判据式结论 + 唯一一句互动钩子

- 判断标准：**Agent 会不会连续自主执行多步操作**——会，就值得一套防打转机制。
- 三板斧组合：画面哈希 + wait-verify + 迭代上限，打转基本无处可逃。
- 单步操作或有严格人工监控时，可简化这套检测。
- 一句话收束：**GUI 打转是感知盲区，不是模型笨——给它「画面没变」的信号就能停**。
