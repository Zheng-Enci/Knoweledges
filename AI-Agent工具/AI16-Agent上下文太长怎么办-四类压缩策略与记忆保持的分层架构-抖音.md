## P01 · 封面

> 卡片职责：抛钩子 + 定锚主题，点破「Agent 上下文」核心名词

- **Agent 上下文太长怎么办？**
- 副标题：四类压缩策略 + 最近上下文怎么传
- 核心数字：**4 类**策略组合，不是四选一

## P02 · 先看上下文被谁撑爆

> 卡片职责：讲三个增长源，建立问题认知

- Agent 跑长任务，上下文只在三处膨胀：对话历史、工具返回结果、模型思考链。
- 对话历史是「慢增长」：一轮一轮往上爬，大部分已无关。
- 工具结果是「尖峰」：读一个 500 行文件，一次就顶上去。
- 思考链是「高消耗低价值」：占地方，但对后续决策帮助有限 📉。

## P03 · 塞太满的代价：超限与注意力涣散

> 卡片职责：讲不处理的后果，制造紧迫感

- 上下文塞太满，最直接是**报错超限**，请求直接被拒。
- 更隐蔽的是「注意力涣散」：长上下文里关键信息被稀释，模型开始漏看走神。
- 所以不是「窗口够大就行」——再大的窗口也会满，也会涣散。
- 类比 🎭：像书桌摊太多资料，找不到东西还容易撞倒水杯 😵。

## P04 · 四类策略总览：丢弃压缩卸载检索

> 卡片职责：给全局框架，为后面铺垫

- **丢弃**：滑动窗口，只留最近 N 轮，最简单。
- **压缩**：把历史摘要成一段话，保留语义。
- **卸载**：全文存外部，上下文只放预览（offloading）。
- **检索**：按 ID 或向量，需要时把记忆拉回来 🎯。

## P05 · 最近上下文怎么传：滑动窗口

> 卡片职责：直接回答「最近上下文怎么传」

- 最直接的答案就是**滑动窗口**：只保留最近 N 轮，更早的丢弃。
- 实现极简：维护固定长度队列，超了弹最老的，成本几乎为零。
- 适合短期任务：客服对话、单轮代码调试。
- 缺陷：**丢失长期信息**，用户问「昨天提的方案」就答不上 ⚠️。

## P06 · 摘要压缩：把历史折叠成纪要

> 卡片职责：讲策略二，补滑动窗口丢信息的洞

- 滑动窗口丢信息，**摘要**来补：把较早历史压成一段「发生了什么」。
- 做法：最近 N 轮原样 + 更早的压成摘要放最前。
- 收益：十轮对话压成两三句，信息密度高；代价是有细节损失。
- 类比 🎭：像会议纪要，两小时压成一页，只记「决定了什么、下一步做啥」 📝。

## P07 · 卸载 offloading：模型只看预览

> 卡片职责：讲策略三，专治工具尖峰

- 摘要治「历史太多」，**卸载**治「单次结果太大」。
- 做法：大块内容存外部，上下文只放短预览 + 可寻址引用。
- 效果：模型看到「已读取 config.py（128 行）」，而不是 128 行全文。
- 类比 🎭：像把大衣存衣帽间，手上只拿号码牌，需要凭号去取 🧥。

## P08 · 检索召回：按需把记忆拉回来

> 卡片职责：讲策略四，长期记忆关键

- 前三种在「省」，**检索**在「按需取」，这是长期记忆的入口。
- 两种召回：向量检索按语义找，ID 可寻址召回按明确编号取（更精准）。
- 优势：记忆容量近乎无限，上下文只放当前需要的部分。
- 类比 🎭：像图书馆查书，书架装无数本，按索引只借你要的那几本 📚。

## P09 · 组合打法：短期窗口加长期记忆

> 卡片职责：把四策略合成分层架构，收束全篇

- **分层结构**：系统提示常驻 → 历史摘要 → 检索注入 → 最近 N 轮原样。
- 短期层答「最近上下文怎么传」：窗口保留最近，系统提示与目标常驻。
- 长期层答「怎么保持记忆」：大结果卸载、久远摘要、关键事实检索。
- 一句话：**最前永远在、目标压成段、旧事存抽屉、最近原样带、需要再召回** ✅。

## P10 · 判断收尾 + 互动钩子

> 卡片职责：给判据式结论 + 唯一一句互动钩子

- 判断标准：**Agent 会不会长期跑、信息量是否持续增长**——会，就上分层。
- 长任务多轮对话频繁读大文件：滑动窗口 + 摘要 + 卸载 + 检索是刚需。
- 任务很短、远没到上限：一个滑动窗口就够，别过度设计。
- 一句话收束：**上下文管理不是删内容，是分层——桌上留最近的，抽屉存久远的**。
