## P01 · 封面

> 卡片职责：抛钩子 + 定锚主题，点破「渐进式披露」核心名词

- **Agent 海量输出怎么折叠才爽？**
- 不是藏起来，是分层呈现
- 第一层只留 **10%** 信号，**90%** 噪音折叠收起

## P02 · 先看清：Agent 输出为什么淹死人

> 卡片职责：讲问题严重性，建立折叠必要性

- 一个 Agent 跑一次任务，会产生四类大量输出：思考过程、工具调用、命令执行、中间结果。
- 思考链几千字、工具调用上百步、命令日志上千行、读到文件内容一堆。
- 全平铺到界面上，结果就是**用户刷很多屏都看不到最终答案**。
- 类比 🎭：像把菜谱、采购单、洗碗记录全塞给你当菜单，信息不是越多越好 📉。

## P03 · 核心原则：渐进式披露

> 卡片职责：给底层原则，解释「渐进」含义

- 底层原则叫**渐进式披露（Progressive Disclosure）**：默认给干净可操作的表面，按需钻取细节。
- 「渐进」= 从概要到证据再到原始轨迹，**逐层展开**，不一次性倒给用户。
- 它专治 Agent 的认知过载：推理轨迹、工具调用、中间结果直接倒 UI 就是灾难。
- 一句话：**默认收敛到结果，过程按需展开** 🎯。

## P04 · 三层信息架构：结论、证据、轨迹

> 卡片职责：讲分层结构，建立骨架

- 第一层**结论面**：最终答案 + 一句状态，**始终可见**，给所有用户。
- 第二层**证据面**：工具结果、引用、关键数据，折叠成一行摘要，给想核对的人。
- 第三层**原始轨迹**：完整思考链、完整日志，深度折叠，给开发调试的人。
- 类比 🎭：像报纸的**标题、导语、全文**，扫标题知大概，想深究再翻全文 🗞️。

## P05 · 折叠四形态：时间、工具、思考、结果

> 卡片职责：讲具体怎么折叠，给四类形态

- 时间折叠：整段思考压成「**思考了 8 秒**」，点开才看完整推理。
- 工具折叠：每次调用收成一行「已读取 config.py」，点开看参数和结果。
- 思考折叠：推理步骤收进可折叠手风琴，默认收起、需要才展开。
- 结果折叠：长输出默认前 N 行 + 「展开全部（共 1200 行）」 📐。

## P06 · 产品实践：Claude Code 怎么做

> 卡片职责：用真实产品佐证，讲时间折叠

- Claude Code 的思考块默认只显示标签「**Thought for 12s**」，点开才看内容。
- 思考用流式推送，界面实时滚动但**不刷屏**，保持清爽。
- 工具调用也流式，运行中显示「**Using Read...**」这类状态，完成折叠成一行。
- 这印证一个规律：**折叠过程细节，不折叠结果** 🔍。

## P07 · 爽感三来源：干净、深挖、反馈

> 卡片职责：拆解「爽感」到底是什么

- **干净**：第一屏就是结果 + 一句状态，不滚动就能知道成没成。
- **深挖**：折叠不是删掉是收起来，想看一次点击就能拿到完整内容。
- **反馈**：折叠状态也要「活着」，有「思考了 8 秒」证明它在干活。
- 类比 🎭：像外卖 App，一眼见「已送达」、点开看轨迹、地图小车一直动，三者齐才爽 🍱。

## P08 · 两种反模式：藏过头 vs 全暴露

> 卡片职责：讲翻车方式，点明分界线

- 反模式一藏过头：把失败、异常、关键证据都折叠了，用户误以为成功。
- 反模式二全暴露：所有过程平铺，用户刷十屏看不到答案，认知过载。
- 分界线：**折叠「过程」，暴露「结果」和「异常」**。
- 尤其失败要优先浮出——错误、验证不通过绝不藏在折叠里 ⚠️。

## P09 · 状态反馈：折叠了也要「活着」

> 卡片职责：讲最易忽略的反馈，补全体验

- 很多工具翻车在反馈：折叠做得漂亮，但没任何「正在干活」提示。
- 用户盯着静止界面猜「是不是卡死了」，体验反而更差。
- 解法：保留一条常驻状态条——「正在读取文件」「运行测试中」「思考了 8 秒」。
- 判断标准：**用户不会因为界面没动静而怀疑卡死** 🔔。

## P10 · 判断收尾 + 互动钩子

> 卡片职责：给判据式结论 + 唯一一句互动钩子

- 判断标准：**用户是不是「只看结果、偶尔看过程」**——是，就该分层折叠。
- 若 Agent 只做单步、或用户就是开发者全程要看 trace，平铺反而更合适。
- 三件事做对才叫爽：默认干净、按需深挖、实时反馈。
- 一句话收束：**折叠的本质是分层呈现，不是隐藏输出**——把信号留下，把噪音收起。
