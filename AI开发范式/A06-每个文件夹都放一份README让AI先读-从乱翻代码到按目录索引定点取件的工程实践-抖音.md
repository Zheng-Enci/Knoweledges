## P01 · 封面

> 卡片职责：抛出核心问题，点明「每个目录一份 README」这个主题，给出核心数字

- 大标题：每个目录都放一份 **README** ，AI 就不乱改文件了？
- 副标题：给 AI 一张目录地图，别再让它瞎翻
- 核心数字：演示仓库 **14** 个目录，补完索引后覆盖率 100%

## P02 · 改错文件多半是缺地图

> 卡片职责：把「AI 改错文件」从能力问题重新定义成信息问题

- AI 接到任务时只能看到文件路径和搜索结果，看不到你脑子里的架构图。
- 同名的 utils 文件在结果列表里长得一模一样，它选哪个全看读到第几条停手。
- 这不是模型笨，是 **信息缺失** ：从没人告诉它两份 utils 各自归谁管。
- 所以要在它试探之前先塞地图，而且必须是 **分层** 地图，不是根目录那份大文档。😐

## P03 · 越层的改动没有成本感

> 卡片职责：说明越层改动为什么难靠 review 拦住，必须靠目录说明兜底

- 人看到跨包的 import 会停一下手，AI 不会，它只觉得这个函数不够用。
- 它的解法常常是就地内联一份实现，diff 里只有几行，却 **破坏封装** 。
- 同一份逻辑出现两处，三个月后两边各自演化，谁也不敢删掉其中一份。⚠️
- 这类改动只能靠目录说明里写清 **边界** 来挡，靠人工 review 是抓不完的。

## P04 · 试探会把上下文吃光

> 卡片职责：给出探索成本的具体机制，并用超市标签类比索引的价值

- AI 的默认动作是层层列目录加反复开文件，每次试探都在消耗 **上下文** 。
- 等它终于摸对文件，上下文已经用掉一半，剩下的一半要留给写代码和自检。
- 比喻：没标签的超市只能一排排拿起来看生产日期，有标签直接走到 **第 3 排** 。🛒
- 索引就把「广度试探」换成「按路径直达」，成本固定，不随仓库变大而涨价。

## P05 · 规则只有三条，缺一就废

> 卡片职责：给出整套约定的三条硬规则，为后面的模板和提示词铺垫

- 第一条： **一层一份** ，根目录加每个子目录各一份，不许写一份大而全的。
- 第二条：只写直系，本层只写自己门口的文件和文件夹，不展开子目录细节。
- 第三条： **先读后改** ，先读目标目录那份，再向上读一层父目录补背景。
- 三条合起来才省时间；少了任何一条，都退化成多读一份没人维护的文档。✅

## P06 · 只写直系才活得久

> 卡片职责：解释「只写直系」这条规则背后的维护成本逻辑

- 一旦允许顺手把下层细节也写进来，同一件事就有了两处描述。
- 两处描述必然在几个月内 **互相矛盾** ，AI 读到哪份算哪份，比不写还糟。
- 每份只写本层就能压在 **30 行** 内，谁建目录谁写，作者就是唯一负责人。📝
- 写不下本身就是信号：说明这个目录该拆了，规则顺带成了目录健康度探针。

## P07 · 把「先读」写成硬约束

> 卡片职责：给出可抄进规则文件的提示词写法，强调冲突时以代码为准

- 写成「建议先阅读相关文档」，AI 一律跳过；必须写成 **条件加动作** 才算数。
- 要抄进规则的就一句核心：改任何文件前，先读它所在目录的 README。
- 目标目录缺 README 就先补一份再改，别跳过，也别只写一句放工具函数。
- 还要补一条：文档和代码冲突时 **以代码为准** ，并在同一次改动里修文档。🔧

## P08 · 实测 14 个目录只覆盖 64.3%

> 卡片职责：用可复算的实测数据说明缺口位置，而不是编一个提效百分比

- 我搭了一棵 14 个目录的演示树，只给根目录和中间层写了 9 份 README。
- 跑检查器：覆盖率 **64.3%** ，缺的 5 个目录全部落在 src 的叶子层。
- 原因是人写文档的直觉偏向高层，AI 出错的位置却天然在底层，两个方向正好错开。
- 补齐这 5 份后再跑一次，覆盖率 **100%** ，退出码从 1 变 0，可以直接卡 CI。📊

## P09 · README 和 AGENTS.md 别混写

> 卡片职责：划清索引文件与规则文件的分工，避免把两类内容挤进一份文件

- 两者答的不是同一个问题：README 说 **这个目录有什么** ，规则文件说这里必须怎么做。
- 规则类文件有 **就近生效** 机制，离被改文件最近的那份优先，子目录能盖父目录。
- README 没有这种机制，它靠提示词里那句「先读」才活，别指望它自动生效。
- 混写在一份文件里，既破坏索引的稳定结构，又让约束散落在描述中间找不到。⚖️

## P10 · 什么时候才值得铺这套

> 卡片职责：给出适用判据与不该用的场景，末页收一句互动钩子

- 目录超过十个、AI 每周要在这里改五次以上代码，这套 README 才谈得上回本。
- 单层小工具、纯生成的构建产物目录、第三方 vendor， **不该写** ，写了也是废纸。
- 判断标准只有一条：这个目录会不会有人在 **三个月** 后回来改它。💡
- 你踩过哪种：A 让 AI 自己翻目录，B 先铺一份索引。选 A 扣 1，选 B 扣 2。
