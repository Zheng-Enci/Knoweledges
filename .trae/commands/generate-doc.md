严格依据 **`.trae/rules/system-prompt.md`**（`项目根目录/.trae/rules/system-prompt.md`）、**`.trae/rules/联网搜索与参考链接规范.md`**（`项目根目录/.trae/rules/联网搜索与参考链接规范.md`）和 **样例文档**（见 `.trae/rules/文档写作铁律.md` 的 T7）的写法生成一篇我所描述的文档 📄

本 command 的产出分两层：**母稿**（即 CSDN + 掘金版，按上述全部规则生成）与**平台变体**（知乎 / 小红书 / 抖音，由母稿派生）📚

## 📦 产出结构（Output Layout）

**一次执行固定产出 4 个 `.md`，全部放在母稿所在专栏目录下。** 🔒

| 序号 | 产出 | 文件名 | 平台 |
|---|---|---|---|
| 1 | 母稿 | `{编号}-{长尾词标题}.md` | CSDN + 掘金 |
| 2 | 变体 | `{母稿名}-知乎.md` | 知乎 |
| 3 | 变体 | `{母稿名}-小红书.md` | 小红书 |
| 4 | 变体 | `{母稿名}-抖音.md` | 抖音 |

- 变体文件名 = 母稿完整文件名（含编号）+ `-{平台名}`，编号与主标题主题必须与母稿一致 🔗
- 母稿**不加** front-matter；变体**必须加** front-matter（见下节）✅
- 变体与母稿同目录并列，不另建子目录 🚫

## 🔀 平台变体生成（Platform Variants）

母稿定稿后立刻派生三份变体，不询问、不等确认 ✅

### 🧱 变体 front-matter 模板

```yaml
---
platform: 知乎
title: 按平台标题语法重写后的标题
summary: ≤256 字摘要，第一句给结论
tags: [标签1, 标签2, 标签3]
limits: 标题 100 字 / 正文无硬上限
source: {母稿完整文件名}
---
```

- `limits` 按平台实测限制填写；未实测的限制写「未实测」，**不得编造具体数字** ⚠️
- `tags` 最多 5 个，合计不超过平台上限 🏷️

### 📌 改写范围（分平台分级执行）

| 序号 | 改造项 | 知乎 | 小红书 / 抖音 |
|---|---|---|---|
| 1 | 主标题 | 必改 | 必改 |
| 2 | 开头 200 字 | 必改 | 必改 |
| 3 | 小节顺序 | 不动，沿用母稿 | 重排或合并 |
| 4 | 案例 / 举例 | 不动，沿用母稿 | 换成该平台读者熟悉的场景 |
| 5 | 结尾 CTA | 必改 | 必改 |

### 📊 分级篇幅与形态

| 平台 | 标题形态 | 篇幅 | 代码 | 外链 | 结尾 CTA |
|---|---|---|---|---|---|
| 知乎 | 问题式 | 与母稿一致（正文复用） | 沿用母稿 | 不主动放 | 关注 + 专栏 |
| 小红书 | 断言 + 数字（≤64 字） | 800–1500 字 | 不放代码块 | 禁止 | 评论区置顶 |
| 抖音 | 3 秒钩子（标题 ≤20 字、摘要 ≤30 字） | 6–15 页分页，每页 80–200 字 | 不放代码块 | 禁止 | 主页简介 |

- 知乎正文**直接复用母稿**，只重写标题、开头 200 字与结尾 CTA，相当于换壳而非重写 🔁
- 小红书、抖音**豁免** T9 篇幅与 T2 完整代码，只保留结论、清单与对照表的精简形态 📉
- 三份变体一律**不主动放外链**；小红书与抖音正文无外链能力，导流只能靠评论区置顶与主页简介 🔒

### 🎞️ 抖音变体分页结构（强制）

`-抖音.md` 的正文按**图卡页**分块：一页一段，页数 = 图卡张数，发布时按页 1:1 出图，页序与内容不得改动 🔒

每页固定骨架 ✅：

```markdown
## P01 · 封面

> 卡片职责：抛钩子，标题 + 核心数字

- 大标题：{≤20 字}
- 副标题：{≤20 字}
- 核心数字：{一行，必须含数字}
```

| 规则 | 要求 |
|---|---|
| 页码 | `P01` 起连续编号，两位数字，不跳号、不重复、不漏页 |
| 页标题 | 写作 `## P{n} · {页主题}`，页主题 ≤8 字，一眼看出这页讲什么 |
| 卡片职责 | 块引用 `>` 首行必须写「卡片职责：…」，一句话交代本页在整篇里的位置 |
| 正文量 | 无序列表 3–6 项，每项 ≤40 字；全页 80–200 字（表格、条形图页的数据行不计入） |
| 首末页 | `P01` 兼封面（标题 + 核心数字 + 可选页脚），末页必须给判据式结论 |
| 页数 | 6–15 页，按内容定；定稿后页数即固定，不得增删 |
| 特殊版式 | 对照表 / 条形图 / 数字罗列页，列表项以 `- 表格：`、`- 条形图：`、`- 数据：` 开头并逐行写出数据，供图卡渲染脚本直接取用；表格每格 ≤20 字 |

- 分页只服务**排版**，不改写内容：页与页之间不重复同一句话，也不新造母稿没有的数字 🔢
- 正文里**不写**「第 1 页」「接下来划到下一页」这类描述版式的话，卡片的翻页感由图卡本身承担 🚫

### 🔒 变体硬约束

1. **数据一致性** 🔢：变体引用的实测数字、定量结论必须与母稿逐项一致，禁止新造；母稿没有的数字一律不写
2. **通用条款照旧生效** ✅：T1 单一主题、T3 加粗空格、T4 必打比喻、9.4 禁诱导话术，三份变体全部适用
3. **不重复母稿全文** 🚫：小红书、抖音不得整段复制母稿正文；知乎的**正文允许复用母稿**，但标题、开头 200 字与结尾 CTA 必须重写
4. **平台归属可溯源** 🔗：front-matter 的 `source` 必须指向母稿完整文件名

## ✍️ Markdown 加粗与 Emoji 规范

- `**文本**` 前后必须保留空格，紧贴中文字符会导致渲染失败 ❌
- `**` 闭合后必须加空格再放 emoji，否则 Markdown parser 无法正确闭合加粗（如 `**加粗文本** 🎮` 而不是 `**加粗文本**🎮`） ⚠️

## 🎭 文档幽默风格规范

- 生成的文档需在**合适位置**自然融入幽默表达，让内容生动有趣、吸引读者 👀
- 幽默方式：生动比喻、俏皮话、反差梗、自嘲等，避免低级玩笑和冷场 🤣
- 推荐位置：引言、章节小标题、示例注释、结论等自然节点 🎯
- 原则：幽默为内容服务，不喧宾夺主；技术准确性永远优先，不得因搞笑而失真 ✅

## 🚀 自主执行（Autonomous Execution）

**本指令执行期间禁止向用户提问，禁止调用 AskUserQuestion 等确认类工具。** 🔒 需求模糊、素材残缺、专栏归属不明、篇幅取舍一律由我自行决定，写完直接交付。

优先级声明：在 `/文档生成` 场景下，本节优先于 `system-prompt.md` 0.0 的确认原则与 7.4 的四问提问要求 ✅

### 🎯 决策规则（信息缺失时按序套用）

| 缺失项 | 默认决策 |
|---|---|
| 主题边界 | 取素材中出现频率最高的技术主体，按 T1 收窄为单一主题 |
| 专栏归属 | 选已有专栏中主题最贴近的一个，编号在现有最大编号上顺延 |
| 标题与长尾词 | 按 system-prompt 7.3 自拟，不询问 |
| 篇幅 | 按 T9 的 5000–12000 字符 |
| 面试 / 营销视角 | 默认不保留，按 T5 只讲是什么与为什么 |
| 配套资源无公开 URL | 跳过 9.1 开篇资源位，不编造链接 |
| 素材含引流话术 | 直接删除，按 9.4 处理 |
| 文末专栏介绍 | 按 9.2 只写收录范围与更新频率，**禁止写「已发 N 篇」** |
| 变体 front-matter 字段 | 按产物反推填，不留空；平台未实测的限制写「未实测」 |
| 变体平台形态 | 知乎问题式 / 小红书断言 + 数字 / 抖音按 `P01…PN` 分页骨架（6–15 页） |

### 💡 假设声明

动笔前用不超过 3 行写明我设定的前提（主题、专栏、篇幅），随文档一起交付，**不等确认、不阻塞流程** ✅ 声明需同时写明「1 母稿 + 3 变体」的产出范围。

### ⚠️ 唯一例外

素材完全无法辨识主题（空文件、纯乱码）时，不提问、不硬编，直接书面说明无法执行的原因后结束 ❌

## 📄 多文件产出约束（强制）

**一次执行产出 1 母稿 + 3 变体，共 4 个 `.md` 文件。** 🔒 母稿规定「怎么写」，变体由母稿派生，两者都算本 command 的正式交付物。

1. **只允许规定内的文件名** 🚫：重复触发、自查不合规、用户追加要求时，一律用 `SearchReplace` 就地修改已有文件。`-知乎`、`-小红书`、`-抖音` 三个后缀属规定产出，**不算**被禁止的变体文件名；`xxx-2.md`、`xxx（修订版）.md` 仍禁止，也不得在编号分隔符上做变体（如 `LeetCode_2011_...` 与 `LeetCode_2011...` 并存）。
2. **目录只写在正文里** 🚫：`system-prompt.md` 6.1 与 `联网搜索与参考链接规范.md` 第 2 步所说的「生成目录结构」，指正文内的章节骨架，**不得单独落盘成文件**。
3. **母稿超篇幅只压成一篇，且不得提问** ✅：触及 T9 上限时，按 T1 收窄主题边界或压缩冗余段落，把内容压进单篇；**不得拆母稿**，**也不得为此向用户询问是否拆分**（与「自主执行」禁止提问条款一致）。变体数量固定为 3，不得增删。

**唯一例外** ⚠️：用户在同一轮明确要求额外生成某份交付物时，按用户指定数量与边界追加产出。
