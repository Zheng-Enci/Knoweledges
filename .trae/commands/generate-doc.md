严格依据 **`.trae/rules/system-prompt.md`**（`项目根目录/.trae/rules/system-prompt.md`）、**`.trae/rules/联网搜索与参考链接规范.md`**（`项目根目录/.trae/rules/联网搜索与参考链接规范.md`）和 **样例文档**（`Transformer/04-缩放点积注意力代码实现.md`、`LLM-大模型技术专栏/LLM07-MoE 混合专家模型深度解析：从路由机制到专家专业化的迷思.md`、`LLM-大模型技术专栏/LLM22-Jev是什么：AI圈再造新概念？.md`）的写法生成一篇我所描述的文档 📄

## ✍️ Markdown 加粗与 Emoji 规范

- `**文本**` 前后必须保留空格，紧贴中文字符会导致渲染失败 ❌
- `**` 闭合后必须加空格再放 emoji，否则 Markdown parser 无法正确闭合加粗（如 `**加粗文本** 🎮` 而不是 `**加粗文本**🎮`） ⚠️

## 🎭 文档幽默风格规范

- 生成的文档需在**合适位置**自然融入幽默表达，让内容生动有趣、吸引读者 👀
- 幽默方式：生动比喻、俏皮话、反差梗、自嘲等，避免低级玩笑和冷场 🤣
- 推荐位置：引言、章节小标题、示例注释、结论等自然节点 🎯
- 原则：幽默为内容服务，不喧宾夺主；技术准确性永远优先，不得因搞笑而失真 ✅

## 🚀 自主执行（Autonomous Execution）

**本指令执行期间禁止向用户提问，禁止调用 AskUserQuestion 等确认类工具。** 🔒 需求模糊、素材残缺、专栏归属不明、篇幅取舍一律由我自行决定，写完直接交付。

优先级声明：在 `/文档生成` 场景下，本节优先于 `system-prompt.md` 0.0 的确认原则与 7.4 的四问提问要求 ✅

### 🎯 决策规则（信息缺失时按序套用）

| 缺失项 | 默认决策 |
|---|---|
| 主题边界 | 取素材中出现频率最高的技术主体，按 T1 收窄为单一主题 |
| 专栏归属 | 选已有专栏中主题最贴近的一个，编号在现有最大编号上顺延 |
| 标题与长尾词 | 按 system-prompt 7.3 自拟，不询问 |
| 篇幅 | 按 T9 的 5000–12000 字符 |
| 面试 / 营销视角 | 默认不保留，按 T5 只讲是什么与为什么 |
| 配套资源无公开 URL | 跳过 9.1 开篇资源位，不编造链接 |
| 素材含引流话术 | 直接删除，按 9.4 处理 |
| 文末专栏介绍 | 按 9.2 只写收录范围与更新频率，**禁止写「已发 N 篇」** |

### 💡 假设声明

动笔前用不超过 3 行写明我设定的前提（主题、专栏、篇幅），随文档一起交付，**不等确认、不阻塞流程** ✅

### ⚠️ 唯一例外

素材完全无法辨识主题（空文件、纯乱码）时，不提问、不硬编，直接书面说明无法执行的原因后结束 ❌
