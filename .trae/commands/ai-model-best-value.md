## 📂 模型范围与数据源（必读）

本 command 的**模型范围由用户每次输入提供，模型定价一律联网搜索获取**，不写死任何模型名或价格。

- **🎫 模型范围（用户输入）**：每次执行时，**以用户本次输入的模型清单为唯一模型范围**。
  - 执行时**必须**在产出文档开头声明：「**依据我输入的模型，对以上模型进行语言最强、语言最具性价比、多模态最强三个榜单排名**」。
  - 用户输入时说明本次要排行的模型（含品牌、模型名，可选能力说明），据此生成榜单，**不得自行增删模型**。
  - 若用户未提供能力说明，按各模型公开能力（文本生成 / 推理 / 视觉理解等）判断其归属榜单，能力归属不明确的在表内标注「能力待确认」。
- **🌐 定价来源（联网搜索）**：不读取任何本地计费或套餐文件，**模型 API 定价一律通过联网搜索获取**。
  - **定价搜索范围仅限用户本次输入的模型**，清单之外的模型一律不采集、不搜索其价格（benchmark 对比中出现的其他模型仅作参照，不纳入价格采集）。
  - 执行时**必须联网搜索**每个清单内模型在**原厂商官方定价页**（如火山方舟/豆包、DeepSeek、月之暗面 Kimi、智谱、MiniMax 等）的价格，取**国内按量计费**的输入价 / 输出价；**搜索不局限于阿里云百炼**，阿里云百炼等第三方平台仅作补充核对渠道。
  - 若模型标注「限时夜间5折 / 限时8折」等折扣，搜索确认原价与活动价，性价比计算**按活动价口径**（同时注明原价）。
  - 每条定价须标注来源与检索日期（如「火山方舟官方定价页，2026年09月22日检索」）。

## ✅ 前置条件

1. **🕐 获取当前时间**：执行 `Get-Date -Format "yyyy年MM月dd日"` 获取实时时间
2. **📂 确认模型范围**：以**用户本次输入的模型清单**为唯一模型范围，梳理每个模型的品牌 / 模型名 / 能力归属（文本生成、推理、视觉理解等），并在产出文档开头声明「依据我输入的模型，对以上模型进行三个榜单排名」
3. **🔍 联网搜索**：综合搜索用户输入模型的 benchmark 排名、综合评价（不区分写代码/写文本方向）；**同时搜索各模型实测 output tokens/s 速度数据**（来源限公开测速榜，如 ArtificialAnalysis），供榜单②速度系数计算；**API 定价一律联网搜索获取**（优先原厂商官方定价页，不局限于阿里云，阿里云百炼等平台仅作补充核对）
4. **📊 数据来源声明**：文档中所有推荐理由、benchmark 数据、综合评价等核心信息，**必须**基于联网搜索获取的最新资料总结得出，不得凭空编造 🚫；API 定价须标注「联网搜索（来源 + 检索日期）」
5. **⏰ 数据时效性**：必须优先采用搜索到的当前最新 benchmark 数据，在文中注明数据截止时间；定价以联网搜索时刻为准
6. **📈 数据充分性**：如果搜索到的数据不够支撑排名结论，必须继续搜索补充数据，直到搜索不到新数据为止 🔁  
7. **🔗 数据源区分**：必须在文内显式区分两类 benchmark 的数据来源——语言场景采用文本类 benchmark（如 SuperCLUE、LMArena 文本维度、SWE-bench 等）；多模态场景采用视觉/多模态类 benchmark（如 MMMU、MMMU-Pro、OCRBench、MMBench 等），并分别注明各自的数据截止时间
8. **💨 速度数据源**：榜单②所用 output tokens/s 采用公开测速榜实测数据（如 ArtificialAnalysis 的 `median_output_tokens_per_second` 口径），**严禁编造**，须单独注明速度数据的来源与截止时间

## 🎯 范围与约束

- **🌍 覆盖范围**：仅限**用户本次输入的模型**（每次执行随输入变动）
- **🔌 可用性要求**：模型以用户输入清单为准；产出文档中须标注每个模型适用的公开 API 或网页端（联网搜索确认）
- **🧩 能力维度拆分**：本 command 产出**一篇文档、三个独立榜单章节**，按「最强」与「最具性价比」两种口径划分：

  | 榜单 | 模型范围 | 排名口径 | 是否含性价比列 |
  |------|----------|----------|:--------------:|
  | **① 语言最强排行** | 用户输入模型中能力含「文本生成、推理模型」的；**含视觉能力的旗舰模型也可纳入**，并在表内标注「同时具备视觉能力」 | 纯语言 benchmark 得分降序 | ✅ 含 |
  | **② 语言最具性价比排行** | 与榜单①相同的模型范围 | 得分 ÷ 3:1 加权综合成本 × 速度系数 降序 | ✅ 含（即排名依据） |
  | **③ 多模态最强排行** | 用户输入模型中能力含「视觉理解」的 | 多模态（视觉）benchmark 得分降序 | ❌ 不含 |

- **🏅「最强模型」判定口径**：各榜按 benchmark 得分降序排名，**得分最高者即「最强模型」**；若前几名得分相近（差距 < 2 分），则以**项目级 rules 遵循度更高者**为「最强模型」（得分与 Rules 双维度综合）。
- **🏅「最具性价比模型」判定口径**：按性价比数值最高者，即 得分 ÷ 3:1 加权综合成本 × 速度系数 的最大值。
- **👂 听话（遵循 rules 文件）要求**：AI IDE / Agent 场景下，模型是与人协作的 collaborator，而非孤立的 benchmark 冠军。**「聪明但独断专行」的模型会破坏 workflow**，因此模型必须能准确遵从项目级 persistent instructions。本 command 从三处约束：
  - **① 入选门槛**：模型必须**支持并能在 Agent/IDE 场景下稳定遵循项目级 rules 文件**（如 Trae 的 `.trae/rules/`、Claude 的 `CLAUDE.md`、Cursor 的 `.cursorrules` 等机制），否则不计入任一榜单。
  - **② 评分维度**：每个榜单表格**新增「Rules 遵循」列**，标注该模型支持的 rules 机制（如 CLAUDE.md / `.trae/rules` 兼容）+ 实测遵从度（高/中/低，或简述表现）。该维度**独立展示，不强行折算进性价比公式**（因缺乏统一公开 benchmark，强行折算易编造数据，违反数据来源约束）；但**参与「最强模型」的相近得分判定**（见上）。
  - **③ 推荐理由必写项**：每个模型的推荐理由中**必须写明其项目级 rules 遵循能力**（是否支持 rules 文件机制、实测遵从表现），与 benchmark 数据并列。
- **💰 性价比标准**：
  - **综合成本公式**：`综合成本 = 输入价 × 0.75 + 输出价 × 0.25`（input:output = 3:1 加权），单位 RMB/百万 Token。
  - **性价比公式**：`性价比 = benchmark 综合得分 ÷ 综合成本`（榜单①展示列沿用此基础口径）。
  - **⚡ 速度调整性价比公式（榜单②排名依据）**：`速度调整性价比 = benchmark 综合得分 ÷ 综合成本 × 速度系数`。
  - **💨 速度系数**：`速度系数 = 该模型实测 output tokens/s ÷ 榜内最快模型 output tokens/s`，归一至 0~1，最快者为 1.0；数据取自联网搜索的公开测速榜（见前置条件第 8 条），**严禁编造**。
  - **🕳️ 速度数据缺失**：某模型搜不到实测速度时，以**榜内中位速度**代入计算，表内标注「速度数据缺失」，不阻断流程。
  - **语言榜**：benchmark 采用 SuperCLUE 等文本类榜单；**不在公开榜单的模型标注「评分待补」，仍保留排名位置**。
  - **多模态最强榜**：benchmark 采用 MMMU / MMMU-Pro 等视觉类榜单，**只按得分排名，性价比不参与排名、不设列**；评分缺失同样标注「评分待补」。
  - **🚫 不评比生成类模型**：图片生成 / 视频生成 / 语音识别·合成·对话类模型（任务粒度与文本 token 不同，无通用 benchmark，强行折算易编造）**不纳入本文档任何榜单**。

## 📋 文档内容结构

文档需包含**三个独立榜单章节**（同一篇文档内）：

### 🏆 排行榜一：语言最强排行

按 **纯语言 benchmark 综合得分** 降序排列。纳入用户输入模型中能力含「文本生成、推理模型」的，**含视觉能力的旗舰模型可一并纳入**并标注「同时具备视觉能力」。**所有入选模型须满足「听话（遵循 rules 文件）」入选门槛**。N = 用户输入模型中实际纳入语言榜的模型数。

- **榜单开头**：以引用块给出本榜「最强模型」结论（模型名 + 得分 + Rules 遵循级别）。
- **主表**：须包含「Rules 遵循」列与完整定价列（得分 / 输入价 / 输出价 / 综合成本 / 性价比 / Rules 遵循），独立展示，不折算进排名。
- **章节末**：以小结段说明该「最强模型」的入选理由（得分表现 + 得分相近时的 Rules 判定依据）。

每个模型推荐必须包含：

- **💡 推荐理由**（纯语言 benchmark 数据支撑，注明所用 benchmark 来源；缺失标「评分待补」）
- **👂 听话能力**（项目级 rules 遵循：是否支持 CLAUDE.md / `.trae/rules` 等机制、实测遵从度）
- **🌐 适用的公开 API 或网页端**
- **💸 参考定价**（输入价/输出价/3:1 加权综合成本，联网搜索获取，注明活动价口径与检索日期）

### 🏆 排行榜二：语言最具性价比排行

按 **纯语言 benchmark 综合得分 ÷ 3:1 加权综合成本 × 速度系数** 降序排列。模型范围与榜单一相同（**含视觉能力的旗舰模型可一并纳入**）。**所有入选模型须满足「听话（遵循 rules 文件）」入选门槛**。N 与榜单一一致。

- **榜单开头**：以引用块给出本榜「最具性价比模型」结论（模型名 + 速度调整性价比数值 + 综合成本 + 实测速度）。
- **主表**：须包含「Rules 遵循」列、「速度 tokens/s」列、「速度系数」列与完整定价列，速度调整性价比为排名依据。
- **章节末**：以小结段说明该模型的性价比优势来源（得分 × 成本 × 速度组合）。

每个模型推荐必须包含：

- **💡 推荐理由**（纯语言 benchmark 数据支撑，注明所用 benchmark 来源；缺失标「评分待补」）
- **💨 实测速度**（output tokens/s，注明测速数据来源与截止时间；缺失标「速度数据缺失」并说明以中位速度代入）
- **👂 听话能力**（项目级 rules 遵循：是否支持 CLAUDE.md / `.trae/rules` 等机制、实测遵从度）
- **🌐 适用的公开 API 或网页端**
- **💸 参考定价**（输入价/输出价/3:1 加权综合成本，联网搜索获取，注明活动价口径与检索日期）

### 🏆 排行榜三：多模态最强排行

按 **多模态（视觉）benchmark 综合得分** 降序排列。**仅纳入用户输入模型中能力含「视觉理解」的**。**所有入选模型须满足「听话（遵循 rules 文件）」入选门槛**。N = 用户输入模型中实际纳入多模态榜的模型数。**表格不含性价比列**。

- **榜单开头**：以引用块给出本榜「最强模型」结论（模型名 + 视觉得分 + Rules 遵循级别）。
- **主表**：按得分降序，列 得分 / Rules 遵循 / 可用渠道等，**不含性价比列**。
- **章节末**：以小结段说明该「最强模型」的入选理由（视觉得分表现 + 得分相近时的 Rules 判定依据）。

每个模型推荐必须包含：

- **💡 推荐理由**（多模态/视觉 benchmark 数据支撑，注明所用 benchmark 来源；缺失标「评分待补」）
- **👁️ 视觉能力说明**（是否支持图片输入、视觉任务类型）
- **👂 听话能力**（项目级 rules 遵循：是否支持 CLAUDE.md / `.trae/rules` 等机制、实测遵从度）
- **🌐 适用的公开 API 或网页端**
- **💸 参考定价**（输入价/输出价/3:1 加权综合成本，联网搜索获取，注明检索日期）

## ✂️ 文档风格

- 文档**尽可能精简**，只保留结论和关键 benchmark 数据，去掉冗长的背景介绍、术语表、阅读路线图等啰嗦内容 ✂️
- 每个推荐只写：排名 + 推荐理由（benchmark 数据支撑）+ 可用渠道 + 参考定价，不展开长篇分析
- 能用表的地方用表，能用一行说清的不写一段 📊
- 三个榜单章节保持结构对称、风格统一，仅 benchmark 口径与 capability 门槛不同
- **所有定价须标注来源**：「联网搜索（来源 + 检索日期）」
