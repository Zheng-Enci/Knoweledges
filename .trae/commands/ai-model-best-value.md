- **🔢 文档编号**：接续现有 LLM 系列编号，执行时取当前最大 LLM 编号 +1（如当前最大为 LLM13，则新文档为 `LLM14`）
- **📝 文件命名**：`{编号}-{文档标题}.md`，标题需精炼概括内容（如 `LLM14-2026年国内AI大模型性价比排行榜：纯语言与多模态双榜单.md`）

- **📦 资源目录**：无需创建 resources 目录（本文档无外部资源引用）

## 📂 动态数据源（必读）

本 command 的**模型范围与定价均从本地动态文件读取**，不写死任何模型名或价格。套餐与计费文件会随订阅变动，每次执行必须重新读取。

- **🎫 套餐文件（模型范围来源）**：`通用资料/阿里云百炼-Standard套餐.md`（相对项目根目录）
  - 执行时**必须读取该文件**，提取「可使用模型」清单（含品牌、模型名、模型能力、限时折扣备注）作为本次榜单的**唯一模型范围**。
  - 套餐文件是动态的，随时可能增删模型或调整折扣，**严禁**在本文档或产出文档中硬编码模型清单。
- **💰 计费文件（定价来源）**：`通用资料/阿里云百炼-模型调用计费.md`（相对项目根目录）
  - 执行时**必须读取该文件**，按模型名提取实时 API 定价（输入价 / 输出价）。
  - 计费文件较大（>128KB），使用 **Grep 工具按模型名搜索**提取对应行，禁止整文件 Read。
  - 若套餐标注「限时夜间5折 / 限时8折」等折扣，从计费文件确认原价与活动价，性价比计算**按活动价口径**（同时注明原价）。
- **⚠️ 路径约定**：以上路径均为**相对项目根目录**的路径，执行时先定位知识库根目录再拼接。

## ✅ 前置条件

1. **🕐 获取当前时间**：执行 `Get-Date -Format "yyyy年MM月dd日"` 获取实时时间
2. **📂 读取动态数据源**：先读取套餐文件锁定模型范围，再读取计费文件提取定价（见上「动态数据源」）
3. **🔍 联网搜索**：综合搜索套餐支持模型的 benchmark 排名、综合评价（不区分写代码/写文本方向）；**API 定价不联网，一律从计费文件取**
4. **📊 数据来源声明**：文档中所有推荐理由、benchmark 数据、综合评价等核心信息，**必须**基于联网搜索获取的最新资料总结得出，不得凭空编造 🚫；API 定价须标注「取自本地计费文件 `通用资料/阿里云百炼-模型调用计费.md`」
5. **⏰ 数据时效性**：必须优先采用搜索到的当前最新 benchmark 数据，在文中注明数据截止时间；定价以计费文件读取时刻为准
6. **📈 数据充分性**：如果搜索到的数据不够支撑排名结论，必须继续搜索补充数据，直到搜索不到新数据为止 🔁
7. **🔗 数据源区分**：必须在文内显式区分两类 benchmark 的数据来源——纯语言场景采用文本类 benchmark（如 SuperCLUE、LMArena 文本维度、SWE-bench 等）；多模态场景采用视觉/多模态类 benchmark（如 MMMU、OCRBench、MMBench 等），并分别注明各自的数据截止时间

## 🎯 范围与约束

- **🌍 覆盖范围**：仅限「阿里云百炼-Standard套餐.md」支持的模型（动态读取，随套餐变动）
- **🔌 可用性要求**：模型可用性以套餐文件「可使用模型」清单为准，无需额外验证公开 API
- **🧩 三场景拆分**：本 command 产出**一篇文档、三个独立榜单章节**，按套餐标注的「模型能力」将模型分为三类：
  - **纯语言场景**：套餐能力含「文本生成、推理模型」且**不含**「视觉理解」的模型。纯语言模型通常更便宜，绝大多数场景（写代码、写文本、对话）无需图片输入，应优先推荐。
  - **多模态场景**（language + vision）：套餐能力含「视觉理解」的模型（可接受图片输入）。仅在用户确实需要图片输入时才需选用。**判定以套餐文件标注为准**，不额外测试。
  - **生成类场景**（图片/视频/语音）：套餐能力为「图片生成 / 视频生成 / 语音识别 / 语音合成 / 实时语音对话」的模型。此类无通用文本/视觉 benchmark，单独成榜，见下文「生成类榜单」约束。
- **� 听话（遵循 rules 文件）要求**：AI IDE / Agent 场景下，模型是与人协作的 collaborator，而非孤立的 benchmark 冠军。**「聪明但独断专行」的模型会破坏 workflow**，因此模型必须能准确遵从项目级 persistent instructions。本 command 从三处约束：
  - **① 入选门槛**：模型必须**支持并能在 Agent/IDE 场景下稳定遵循项目级 rules 文件**（如 Trae 的 `.trae/rules/`、Claude 的 `CLAUDE.md`、Cursor 的 `.cursorrules` 等机制），否则不计入任一榜单。
  - **② 评分维度**：每个榜单表格**新增「Rules 遵循」列**，标注该模型支持的 rules 机制（如 CLAUDE.md / `.trae/rules` 兼容）+ 实测遵从度（高/中/低，或简述表现）。该维度**独立展示，不强行折算进性价比公式**（因缺乏统一公开 benchmark，强行折算易编造数据，违反数据来源约束）。
  - **③ 推荐理由必写项**：每个模型的推荐理由中**必须写明其项目级 rules 遵循能力**（是否支持 rules 文件机制、实测遵从表现），与 benchmark 数据并列。
- **� 性价比标准（三口径）**：
  - **纯语言榜**：按「纯语言 benchmark 综合得分 ÷ 每百万 tokens 综合成本」排名，其中综合成本按 input:output = 3:1 加权计算（即 综合成本 = 输入价 × 0.75 + 输出价 × 0.25）。benchmark 采用 SuperCLUE 等文本类榜单；**不在公开榜单的模型标注「评分待补」，仍保留排名位置**。
  - **多模态榜**：按「多模态（视觉）benchmark 综合得分 ÷ 每百万 tokens 综合成本」排名，综合成本同样按 3:1 加权。**入选门槛**：套餐能力含「视觉理解」。**评分缺失同样标注「评分待补」**。
  - **生成类榜**：图片/视频/语音生成模型**不套性价比公式**（任务粒度与文本 token 不同，强行折算易编造）。按计费单价（图片：元/张；视频：元/秒；语音：元/分钟或元/次）作为成本列，结合官方宣称的生成质量/分辨率/速度做简述。定价同样取自计费文件。

## 📋 文档内容结构

文档需包含**三个独立榜单章节**（同一篇文档内）：

### 🏆 排行榜一：纯语言场景 性价比 Top N

按 **纯语言 benchmark 综合得分 ÷ 3:1 加权综合成本** 降序排列。仅纳入套餐能力含「文本生成、推理模型」且**不含**「视觉理解」的模型。**所有入选模型须满足「听话（遵循 rules 文件）」入选门槛**。N = 套餐支持的实际纯语言模型数。

每个模型推荐必须包含：

- **💡 推荐理由**（纯语言 benchmark 数据支撑，注明所用 benchmark 来源；缺失标「评分待补」）
- **👂 听话能力**（项目级 rules 遵循：是否支持 CLAUDE.md / `.trae/rules` 等机制、实测遵从度）
- **🌐 适用的公开 API 或网页端**
- **💸 参考定价**（输入价/输出价/3:1 加权综合成本，取自计费文件，注明活动价口径）

表格须包含「Rules 遵循」列，标注支持机制与遵从度（独立展示，不折算进性价比）。

### 🏆 排行榜二：多模态场景（language + vision） 性价比 Top N

按 **多模态（视觉）benchmark 综合得分 ÷ 3:1 加权综合成本** 降序排列。**仅纳入套餐能力含「视觉理解」的模型**。**所有入选模型须满足「听话（遵循 rules 文件）」入选门槛**。N = 套餐支持的实际视觉模型数。

每个模型推荐必须包含：

- **💡 推荐理由**（多模态/视觉 benchmark 数据支撑，注明所用 benchmark 来源；缺失标「评分待补」）
- **👁️ 视觉能力说明**（是否支持图片输入、视觉任务类型）
- **👂 听话能力**（项目级 rules 遵循：是否支持 CLAUDE.md / `.trae/rules` 等机制、实测遵从度）
- **🌐 适用的公开 API 或网页端**
- **💸 参考定价**（输入价/输出价/3:1 加权综合成本，取自计费文件）

表格须包含「Rules 遵循」列，标注支持机制与遵从度（独立展示，不折算进性价比）。

### 🏆 排行榜三：生成类场景（图片 / 视频 / 语音） 单价与能力速览

**不套性价比公式**。按任务类型分组（图片生成 / 视频生成 / 语音识别·合成·对话），列每张/每秒/每分钟单价（取自计费文件）+ 官方质量简述（分辨率、速度、并发等）。

每个模型须包含：

- **💡 能力简述**（生成类型、官方宣称质量/分辨率/速度）
- **🌐 适用的公开 API 或网页端**（套餐专属 Base URL / 百炼控制台）
- **💸 参考单价**（按任务粒度，取自计费文件）

## ✂️ 文档风格

- 文档**尽可能精简**，只保留结论和关键 benchmark 数据，去掉冗长的背景介绍、术语表、阅读路线图等啰嗦内容 ✂️
- 每个推荐只写：排名 + 推荐理由（benchmark 数据支撑）+ 可用渠道 + 参考定价，不展开长篇分析
- 能用表的地方用表，能用一行说清的不写一段 📊
- 三个榜单章节保持结构对称、风格统一，仅 benchmark 口径与 capability 门槛不同
- **所有定价须标注来源**：「取自 `通用资料/阿里云百炼-模型调用计费.md`」
