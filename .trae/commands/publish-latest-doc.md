## 📌 适用场景

执行本 command 时，自动完成「找最新文章组 → 解析 5 个产出 → 生成 3 张封面 → 逐平台发布」全流程 🚀
5 个产出由 `/文档生成` 固定生成：**母稿**（掘金 + CSDN）与 **4 个变体**（知乎 / 腾讯云 / 小红书 / 抖音），一个都不能少。
全程使用**内置浏览器**（browser / Chrome DevTools MCP）操作，不使用平台 API、不修改原文档 ✅

**全自动授权** 🤖：从定位文章到点击发布，全部由 AI 自主决策并执行，**不询问用户、不等待确认**，最终目标是 6 个平台位全部发布成功。遇到不确定的信息，优先参考以下来源自行判断：

1. 该账号**已发布的历史文章**（标题风格、标签、专栏归属、分类选择）
2. 平台页面上的**推荐项与提示文案**（推荐标签、已有专栏列表、字数限制）
3. **本地项目**中的目录结构、`00-xxx链接目录.md` 等既有约定
4. 同组**变体 front-matter** 里已写好的 `title` / `summary` / `tags`

## 1️⃣ 定位最新文章组（Document Group）

在项目根目录执行（Git Bash）：

```bash
find . -name "*.md" \
  -not -path "./.trae/*" \
  -not -path "./.git/*" \
  -not -path "*/resources/*" \
  -not -name "README.md" \
  -not -name "*url链接目录*" \
  -not -name "*目录.md" \
  -not -name "*-知乎.md" \
  -not -name "*-腾讯云.md" \
  -not -name "*-小红书.md" \
  -not -name "*-抖音.md" \
  -printf "%T@ %TY-%Tm-%Td %TH:%TM %p\n" \
  | sort -rn | head -n 5
```

- 🥇 取**母稿 mtime 最新**的一篇作为本轮发布对象，输出前 5 名候选及时间，报告最终选中项及理由
- 🧩 由母稿路径推导整组 5 个文件，缺项直接标「未生成」：

| 产出 | 路径规则 | 发布平台 |
|---|---|---|
| 母稿 | 定位结果 | 掘金 + CSDN |
| 变体 | `{母稿去扩展名}-知乎.md` | 知乎 |
| 变体 | `{母稿去扩展名}-腾讯云.md` | 腾讯云开发者社区 |
| 变体 | `{母稿去扩展名}-小红书.md` | 小红书 |
| 变体 | `{母稿去扩展名}-抖音.md` | 抖音 |

- 🚫 排除项：`.trae/`、`resources/`、`README.md`、各类 `url链接目录`、临时草稿与 `.rendered.html`
- ⚠️ **绝不允许**把变体文件当母稿发到掘金 / CSDN：变体按平台分发，母稿只走长文双平台

## 2️⃣ 解析标题、专栏与 front-matter

| 字段 | 母稿 | 变体 |
|------|------|------|
| **文章标题** | 文件名去扩展名 + 去编号前缀 | front-matter `title`（已按平台语法重写） |
| **摘要** | 按 3️⃣-2 重写 | front-matter `summary`，仅按平台上限压缩 |
| **标签** | 正文 + 文件夹名提取 | front-matter `tags` |
| **专栏名** | 文档所在**文件夹名**（原样保留） | 同上（小红书 / 抖音无专栏，落成话题） |

- 🔢 编号前缀正则：`^[A-Za-z]{0,4}[0-9]+[A-Za-z0-9]{0,6}[-_ ]+`
- 🧪 对照示例：
  - `A04-AI时代什么样的程序员不会被淘汰-知乎.md` → 标题取 `title` 字段，文件名编号不进平台标题
  - `J1C-IDE选择与使用-...` → `IDE选择与使用-...`
  - `09aaa-LayerNorm是什么？` → `LayerNorm是什么？`
  - `@Bean注解基础入门-...` → 无编号，保持不变
- 🔗 **串台校验**：变体 front-matter 的 `source` 必须等于本组母稿完整文件名；不一致即视为串台，停止发布并在汇报里标注
- 🏷️ 标签建议：掘金最多 3 个、CSDN 最多 5 个、知乎话题最多 5 个、腾讯云最多 5 个（均以页面提示剩余数量为准）
- 🎯 自主决策规则：
  - 掘金标签必须从输入框下方的**候选下拉项**中选择，输入后点击匹配项；匹配不到就换相近标签，不硬造
  - CSDN 允许 Enter 键入自定义标签，优先用正文里已写明的标签
  - 分类按正文技术栈选择（Java/Spring 类选「后端」，纯数据库选「后端」，前端框架选「前端」）
  - 专栏优先复用**已存在的同系列专栏**；确实不存在时才新建，名称取文件夹名
  - ✂️ 变体标题超出输入框实时计数上限时，按「**结论 + 关键数字**」压缩，语义不变；**不得新造数字**，母稿没有的数字一律不写
- 🚫 抖音标题、摘要严格控制在 30 字内（front-matter 已按此写），小红书标题以页面实时计数为准

## 2️⃣-2 🎨 生成封面图（三种比例）

刷信息流时用户只能看到三样东西：**标题、摘要、封面图**。三种比例各自独立生成，不能一张横图裁三个平台。

| 用途 | 尺寸 | 落盘路径 | 适用平台 |
|---|---|---|---|
| 横版 | `2560x1440`（16:9） | `Temp/<语义化主题>_2560x1440.png` | 掘金、CSDN、知乎、腾讯云 |
| 竖版 3:4 | `1080x1440` | `Temp/<语义化主题>_1080x1440.png` | 小红书 |
| 竖版 9:16 | `1080x1920` | `Temp/<语义化主题>_1080x1920.png` | 抖音 |

**做法**：调用全局 `/生成图片` 指令（绝对路径 `C:\Users\zheng\.trae-cn\commands\生成图片.md`，不在本项目内）分别生成 3 张，默认不加水印；发布时用 `upload_file` 上传到各平台封面框。

**吸引力公式（按优先级）** 🔥：

1. **夸张情绪的主体**：一张脸或一个拟人化主体占画布 **15% 以上**，表情必须是夸张的惊讶、崩溃或得意——缩到 200px 时，只有极端表情还看得清。带人脸的封面实测点击率高出约 38%。
2. **眼神引流**：主体视线指向标题文字或画面冲突点，读者的眼睛会跟着走。
3. **高对比撞色**：主体与背景用互补色，优先 **黄+黑**（知识类最稳）、红+白；整体按「背景 80% 收敛、主体 20% 高饱和」分配。
4. **给结果、藏方法（悬念）**：画面只呈现冲突的结果，不给出解法——例如「三种写法被硬塞进同一个入口导致连锁改动」，读者必须点进去才知道该怎么分层。
5. **文字极简**：横版最多 5-7 个字，竖版最多 5 个字，粗黑体，字号不小于画布宽的 1/6，且不与文章标题重复。
6. **三元素上限**：主体 + 一个对比物 + 一行字，再多就糊成一团。

**必须贴合文档** 🎯：

- 视觉隐喻直接取自本文的核心冲突（如 A04 是「改一处 vs 改三处」的连锁反应）
- 图上文字只能来自标题或其同义改写，**禁止出现文档里没有的数字、百分比、性能指标**
- 禁止出现真实人物肖像、平台 logo、二维码、水印

**落地检查** ✅：

- 缩小到 300px 宽自查：主体、表情、那行字是否还看得清，看不清就重生成
- 竖版两张额外检查：主体是否落在画布中央安全区，避免平台裁切
- 封面图与正文图片互不影响：正文图仍按第 4 节处理

## 3️⃣ 生成发布稿（不改原文档）

在临时目录为**每个待发布产出各生成一份发布副本**，原文档**只读不写** 🔒

1. **🧾 剥离 front-matter**：变体首部 `---` 包裹的整段 YAML 必须删除，否则会被平台当正文渲染 ⚠️（母稿无 front-matter，本步跳过）
2. **✂️ 去掉正文首个一级标题**：若正文首行是 `# 与标题相同/相近的 H1`，删除该行，避免平台标题与正文标题重复
3. **🖼️ 本地图片转 GitCode Raw URL**：按 `.trae/rules/GitCode图片URL转换规范.md` 转换
   - 基础地址：`https://raw.gitcode.com/ZhengEnCi/knoweledges/raw/master/`
   - `resources/P2L/photo/xx.png` → `https://raw.gitcode.com/ZhengEnCi/knoweledges/raw/master/Python-基础技术/resources/P2L/photo/xx.png`
   - 路径统一正斜杠 `/`，中文与空格做完整 URL 编码 ⚠️
4. **🧾 其余内容原样保留**：不润色、不删改段落、不调整结构 🚫
5. **📵 小红书 / 抖音额外做纯文本化**（这两个平台不渲染 Markdown）：
   - 删掉 `**`、`##`、`>`、行内反引号，把标题降级成口语分段
   - 段间保留空行，避免挤成一坨
   - 话题统一写成 `#标签`，追加在正文末尾，取自 front-matter `tags`
   - 抖音标题取 front-matter `title`，正文直接用纯文本版
6. **🧹 6 个平台位全部发布完成后删除临时发布稿**（中间产物不留存）

## 3️⃣-2 ✍️ 平台摘要撰写（必做，禁止用平台自动提取）

发布面板里的「编辑摘要」（掘金，≤100 字）与「文章摘要」（CSDN，≤256 字）**必须手动重写**，不能保留平台自动提取的内容。摘要是列表页、搜索结果与推荐流里唯一替文章说话的文案，写成正文前 100 字的复制粘贴等于放弃点击率。

**分工** 🔀：

- **母稿**：掘金与 CSDN 各写一版，两版不得完全相同 ✅
- **变体**：直接用 front-matter `summary`（已是按平台改写的手写稿），只需按平台上限压缩，**不得替换成平台自动提取内容**

**写作规则** 🔥：

1. **开头 15 字内抛痛点或反常识结论**：不用「本文介绍了」「随着……的发展」这类开场
2. **中段给具体交付物**：几张表、哪几条约束、能解决什么答辩问题；用名词和数字，不喊口号
3. **结尾留一个具体钩子**：老师最爱追问什么、哪一步最容易翻车
4. **自然嵌入 1-2 个搜索关键词**（如「代码组织」「改动成本」），保证长尾搜索命中
5. **禁止**：编造数据、夸大承诺、「史上最全」「干货满满」「包过」「一键搞定」
6. **禁止直接复制正文首段**：摘要要能脱离正文独立阅读

**模板** 🧩：

```
{痛点或反常识结论}：{具体做法 + 关键数字}。{读者能拿走什么}，{留一个钩子}。
```

**落地检查** ✅：

- 填完后读取输入框 `value`，确认字数未超限、无残留的自动摘要
- 掘金摘要框默认是 100/100 的自动内容，需**全选覆盖**
- CSDN 摘要框默认 0/256，可点「AI 提取摘要」后**再手动改写**，但不得原样提交

## 4️⃣-2 🧪 配套资源链接预热（重点）⚠️

正文里的「📦 配套资源」直链（`.py` / `.java` / `.sql` / `.zip` / `.json` 等**非图片**文件）指向 `raw.gitcode.com`。该域名是 CDN，仓库文件首次被访问时可能返回 404、空白页或占位内容——只有先在浏览器里真实走到该文件、触发一次回源，raw URL 才会稳定可下载。因此发布前必须做一次「模拟人工点击」的预热，**不能直接拿未验证的 URL 去发布**。

**触发条件**：发布稿中存在 `https://raw.gitcode.com/...` 且后缀不是图片（`.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.svg`）的链接，或正文出现 `> 📦 配套资源：` 行。命中即必须执行，不得跳过。母稿命中即视为全组命中，只需预热一次。

**做法** 🔧：

1. **列出清单**：从发布稿中抽出全部资源 URL，逐个做 URL decode 得到仓库相对路径，整理成「URL → 相对路径」对照表
2. **进仓库首页**：`navigate_page` 打开 `https://gitcode.com/ZhengEnCi/knoweledges`，`take_snapshot` 确认页面正常渲染（不是 404、不是登录墙）
3. **模拟人工点击**：在文件树里**逐级点击**目录（如 `AI开发范式` → `resources` → `A04` → `code`），最后点击目标文件名进入 blob 页面
   - 必须真的点开每一级目录和文件，**不能只改地址栏直达**：本步骤的目的就是让 CDN 记录该路径的回源请求
   - 目录层级必须与正文 URL 的相对路径完全一致，大小写、中文、空格都不能改
4. **确认文件内容**：blob 页面渲染出真实源码（能看到首行代码），而不是「文件不存在」提示
5. **再点 Raw**：点击页面上的「原始数据 / Raw」按钮打开 raw 页面，确认返回的是**纯文本源码**
6. **刷新校验**：在该 raw 标签页 `navigate_page` 重新加载一次，仍能拿到内容，才算预热成功
7. **逐个复测**：对清单里每个资源 URL 重复第 2–6 步，全部通过后才允许进入发布
8. **兜底替换**：若某条 raw 链接重试 2 次仍 404 或空白，改用仓库 blob 页面 URL（`https://gitcode.com/ZhengEnCi/knoweledges/blob/master/{编码后的相对路径}`）替换正文该处链接，并在汇报里注明替换原因
9. **回写发布稿**：预热过程只允许调整链接形式，**不得改写资源名称、说明文字、所在段落** 🚫

**落地检查** ✅：

- [ ] 发布稿里每个资源链接都在浏览器里真实点开过，且 raw 返回纯文本源码
- [ ] 没有一条链接是「点开 404 / 空白 / 登录页」
- [ ] 正文「📦 配套资源」里的链接，与浏览器里实际打开的地址完全一致
- [ ] 若发生 blob 替换，已记录到汇报
