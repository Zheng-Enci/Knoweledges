## 📌 适用场景

执行本 command 时，自动完成「找最新文章组 → 解析 2 个产出 → 生成封面 → 逐平台发布」全流程 🚀
2 个产出由 `/文档生成` 固定生成：**母稿**（掘金 + CSDN）与 **1 个变体**（抖音），一个都不能少。
全程使用**内置浏览器**（browser / Chrome DevTools MCP）操作，不使用平台 API、不修改原文档 ✅

**全自动授权** 🤖：从定位文章到点击发布，全部由 AI 自主决策并执行，**不询问用户、不等待确认**，最终目标是 3 个平台位全部发布成功。遇到不确定的信息，优先参考以下来源自行判断：

1. 该账号**已发布的历史文章**（标题风格、标签、专栏归属、分类选择）
2. 平台页面上的**推荐项与提示文案**（推荐标签、已有专栏列表、字数限制）
3. **本地项目**中的目录结构、`00-xxx链接目录.md` 等既有约定
4. 同组**变体 front-matter** 里已写好的 `title` / `summary` / `tags`

## 1️⃣ 定位最新文章组（Document Group）

在项目根目录执行（Git Bash）：

```bash
find . -name "*.md" \
  -not -path "./.trae/*" \
  -not -path "./.git/*" \
  -not -path "*/resources/*" \
  -not -name "README.md" \
  -not -name "*url链接目录*" \
  -not -name "*目录.md" \
  -not -name "*-知乎.md" \
  -not -name "*-腾讯云.md" \
  -not -name "*-小红书.md" \
  -not -name "*-抖音.md" \
  -printf "%T@ %TY-%Tm-%Td %TH:%TM %p\n" \
  | sort -rn | head -n 5
```

- 🥇 取**母稿 mtime 最新**的一篇作为本轮发布对象，输出前 5 名候选及时间，报告最终选中项及理由
- 🧩 由母稿路径推导整组 2 个文件，缺项直接标「未生成」：

| 产出 | 路径规则 | 发布平台 |
|---|---|---|
| 母稿 | 定位结果 | 掘金 + CSDN |
| 变体 | `{母稿去扩展名}-抖音.md` | 抖音 |

- 🚫 排除项：`.trae/`、`resources/`、`README.md`、各类 `url链接目录`、临时草稿与 `.rendered.html`
- 🗂️ `*-知乎.md`、`*-小红书.md`、`*-腾讯云.md` 为历史遗留变体，已停止生成与发布，保留在 `find` 排除列表里，防止被误当母稿选中
- ⚠️ **绝不允许**把变体文件当母稿发到掘金 / CSDN：变体按平台分发，母稿只走长文双平台

## 2️⃣ 解析标题、专栏与 front-matter

| 字段 | 母稿 | 变体 |
|------|------|------|
| **文章标题** | 文件名去扩展名 + 去编号前缀 | front-matter `title`（已按平台语法重写） |
| **摘要** | 按 3️⃣-2 重写 | front-matter `summary`，仅按平台上限压缩 |
| **标签** | 正文 + 文件夹名提取 | front-matter `tags` |
| **专栏名** | 文档所在**文件夹名**（原样保留） | 同上（抖音无专栏，落成话题） |

- 🔢 编号前缀正则：`^[A-Za-z]{0,4}[0-9]+[A-Za-z0-9]{0,6}[-_ ]+`
- 🧪 对照示例：
  - `A04-AI时代什么样的程序员不会被淘汰-抖音.md` → 标题取 `title` 字段，文件名编号不进平台标题
  - `J1C-IDE选择与使用-...` → `IDE选择与使用-...`
  - `09aaa-LayerNorm是什么？` → `LayerNorm是什么？`
  - `@Bean注解基础入门-...` → 无编号，保持不变
- 🔗 **串台校验**：变体 front-matter 的 `source` 必须等于本组母稿完整文件名；不一致即视为串台，停止发布并在汇报里标注
- 🏷️ 标签建议：掘金最多 3 个、CSDN 最多 5 个（均以页面提示剩余数量为准）
- 🎯 自主决策规则：
  - 掘金标签必须从输入框下方的**候选下拉项**中选择，输入后点击匹配项；匹配不到就换相近标签，不硬造
  - CSDN 允许 Enter 键入自定义标签，优先用正文里已写明的标签
  - 分类按正文技术栈选择（Java/Spring 类选「后端」，纯数据库选「后端」，前端框架选「前端」）
  - 专栏优先复用**已存在的同系列专栏**；确实不存在时才新建，名称取文件夹名
  - ✂️ 变体标题超出输入框实时计数上限时，按「**结论 + 关键数字**」压缩，语义不变；**不得新造数字**，母稿没有的数字一律不写
- 🚫 抖音标题严格控制在 20 字内、摘要控制在 30 字内（front-matter 已按此写）

## 2️⃣-2 🎨 生成封面图（两种比例）

刷信息流时用户只能看到三样东西：**标题、摘要、封面图**。两种比例各自独立生成，不能一张横图裁两个平台。

| 用途 | 尺寸 | 落盘路径 | 适用平台 |
|---|---|---|---|
| 横版 | `2560x1440`（16:9） | `Temp/<语义化主题>_2560x1440.png` | 掘金、CSDN |
| 竖版 3:4 | `1080x1440` | `Temp/<语义化主题>_1080x1440.png` | 抖音图文卡片（`P01` 兼封面，见第 7️⃣ 节） |

> ⚠️ **横版是「缩略图工程」**：掘金 / CSDN 列表卡片里这张 16:9 图的实际展示宽度只有 **200–350 px**，字号按 `2560` 画布设计时很容易写成「只有原图看得清」，读者在信息流里看到的是一团糊。横版一切设计以「缩到 350 px 还读得出来」为唯一标准。

**做法**：调用全局 `/生成图片` 指令（绝对路径 `C:\Users\zheng\.trae-cn\commands\生成图片.md`，不在本项目内）分别生成 2 张，默认不加水印；发布时用 `upload_file` 上传到各平台封面框。

**🖥️ 本机 Python 环境（需要代码绘制图片时用）** 🔒：

| 项 | 值 |
|---|---|
| 解释器 | `C:\Users\zheng\OneDrive\Desktop\CodeEnvironment\miniconda3\python.exe` |
| 版本 | Python 3.14.7（Anaconda 打包版） |
| 已装库 | Pillow 13.0.0 |
| 字体 | `C:\Windows\Fonts\msyh.ttc`（微软雅黑）、`consola.ttf`（等宽） |
| 调用方式 | **必须写全路径**：`python`、`py`、`python3` 都不在 `PATH` 上，直接调用会返回 `Python was not found` |
| 相邻工具 | `CodeEnvironment\ms-playwright`（需要 HTML 截图时可用）、`CodeEnvironment\ffmpeg-*` |

> ⚠️ 按 `Python命令行绘图规范.md`：一律用 `python -c` 内联执行，或在 `Temp/` 下写临时脚本、用完即删，**不得在项目目录留 `.py` 文件**。

**吸引力公式（按优先级）** 🔥：

1. **夸张情绪的主体**：一张脸或一个拟人化主体占画布 **15% 以上**，表情必须是夸张的惊讶、崩溃或得意——缩到 200px 时，只有极端表情还看得清。带人脸的封面实测点击率高出约 38%。
2. **眼神引流**：主体视线指向标题文字或画面冲突点，读者的眼睛会跟着走。
3. **高对比撞色**：主体与背景用互补色，优先 **黄+黑**（知识类最稳）、红+白；整体按「背景 80% 收敛、主体 20% 高饱和」分配。
4. **给结果、藏方法（悬念）**：画面只呈现冲突的结果，不给出解法——例如「三种写法被硬塞进同一个入口导致连锁改动」，读者必须点进去才知道该怎么分层。
5. **文字要大，字少字大**：横版主标题 **5–7 个字、字号 ≥ 画布宽的 1/10**（`2560` 画布 → 实际 ≥ `256 px`）；副标题／数字 **字号 ≥ 画布宽的 1/18**（≥ `140 px`）；全图文字总量 ≤ 20 字。**字多就砍字，禁止靠缩小字号塞进去**。竖版最多 5 个字，字号 ≥ 画布宽的 1/8。粗黑体，且不与文章标题重复。
6. **三元素上限**：主体 + 一个对比物 + 一行字，再多就糊成一团。

**必须贴合文档** 🎯：

- 视觉隐喻直接取自本文的核心冲突（如 A04 是「改一处 vs 改三处」的连锁反应）
- 图上文字只能来自标题或其同义改写，**禁止出现文档里没有的数字、百分比、性能指标**
- 禁止出现真实人物肖像、平台 logo、二维码、水印

**落地检查** ✅：

- **横版按 350 px 宽自查**（掘金 / CSDN 列表卡片的真实展示尺寸）：主标题折合字高 ≥ `35 px`、副标题 ≥ `19 px`，且不出现整段小字说明；看不清就**放大字号或砍字**后重出图，不得原样上架
- **竖版缩到 300 px 宽自查**：主体、表情、那行字是否还看得清，看不清就重生成
- 竖版额外检查：主体是否落在画布中央安全区，避免平台裁切
- 封面图与正文图片互不影响：正文图仍按第 4 节处理

## 3️⃣-2 ✍️ 平台摘要撰写（必做，禁止用平台自动提取）

发布面板里的「编辑摘要」（掘金，≤100 字）与「文章摘要」（CSDN，≤256 字）**必须手动重写**，不能保留平台自动提取的内容。摘要是列表页、搜索结果与推荐流里唯一替文章说话的文案，写成正文前 100 字的复制粘贴等于放弃点击率。

**分工** 🔀：

- **母稿**：掘金与 CSDN 各写一版，两版不得完全相同 ✅
- **变体**：直接用 front-matter `summary`（已是按平台改写的手写稿），只需按平台上限压缩，**不得替换成平台自动提取内容**

**写作规则** 🔥：

1. **开头 15 字内抛痛点或反常识结论**：不用「本文介绍了」「随着……的发展」这类开场
2. **中段给具体交付物**：几张表、哪几条约束、能解决什么答辩问题；用名词和数字，不喊口号
3. **结尾留一个具体钩子**：老师最爱追问什么、哪一步最容易翻车
4. **自然嵌入 1-2 个搜索关键词**（如「代码组织」「改动成本」），保证长尾搜索命中
5. **禁止**：编造数据、夸大承诺、「史上最全」「干货满满」「包过」「一键搞定」
6. **禁止直接复制正文首段**：摘要要能脱离正文独立阅读

**模板** 🧩：

```
{痛点或反常识结论}：{具体做法 + 关键数字}。{读者能拿走什么}，{留一个钩子}。
```

**落地检查** ✅：

- 填完后读取输入框 `value`，确认字数未超限、无残留的自动摘要
- 掘金摘要框默认是 100/100 的自动内容，需**全选覆盖**
- CSDN 摘要框默认 0/256，可点「AI 提取摘要」后**再手动改写**，但不得原样提交

## 4️⃣-2 🧪 配套资源链接预热（重点）⚠️

正文里的「📦 配套资源」直链（`.py` / `.java` / `.sql` / `.zip` / `.json` 等**非图片**文件）指向 `raw.gitcode.com`。该域名是 CDN，仓库文件首次被访问时可能返回 404、空白页或占位内容——只有先在浏览器里真实走到该文件、触发一次回源，raw URL 才会稳定可下载。因此发布前必须做一次「模拟人工点击」的预热，**不能直接拿未验证的 URL 去发布**。

**触发条件**：发布稿中存在 `https://raw.gitcode.com/...` 且后缀不是图片（`.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.svg`）的链接，或正文出现 `> 📦 配套资源：` 行。命中即必须执行，不得跳过。母稿命中即视为全组命中，只需预热一次。

**做法** 🔧：

1. **列出清单**：从发布稿中抽出全部资源 URL，逐个做 URL decode 得到仓库相对路径，整理成「URL → 相对路径」对照表
2. **进仓库首页**：`navigate_page` 打开 `https://gitcode.com/ZhengEnCi/knoweledges`，`take_snapshot` 确认页面正常渲染（不是 404、不是登录墙）
3. **模拟人工点击**：在文件树里**逐级点击**目录（如 `AI开发范式` → `resources` → `A04` → `code`），最后点击目标文件名进入 blob 页面
   - 必须真的点开每一级目录和文件，**不能只改地址栏直达**：本步骤的目的就是让 CDN 记录该路径的回源请求
   - 目录层级必须与正文 URL 的相对路径完全一致，大小写、中文、空格都不能改
4. **确认文件内容**：blob 页面渲染出真实源码（能看到首行代码），而不是「文件不存在」提示
5. **再点 Raw**：点击页面上的「原始数据 / Raw」按钮打开 raw 页面，确认返回的是**纯文本源码**
6. **刷新校验**：在该 raw 标签页 `navigate_page` 重新加载一次，仍能拿到内容，才算预热成功
7. **逐个复测**：对清单里每个资源 URL 重复第 2–6 步，全部通过后才允许进入发布
8. **兜底替换**：若某条 raw 链接重试 2 次仍 404 或空白，改用仓库 blob 页面 URL（`https://gitcode.com/ZhengEnCi/knoweledges/blob/master/{编码后的相对路径}`）替换正文该处链接，并在汇报里注明替换原因
9. **回写发布稿**：预热过程只允许调整链接形式，**不得改写资源名称、说明文字、所在段落** 🚫

**落地检查** ✅：

- [ ] 发布稿里每个资源链接都在浏览器里真实点开过，且 raw 返回纯文本源码
- [ ] 没有一条链接是「点开 404 / 空白 / 登录页」
- [ ] 正文「📦 配套资源」里的链接，与浏览器里实际打开的地址完全一致
- [ ] 若发生 blob 替换，已记录到汇报

#### 7.1.0 卡内排版细则（垂直分布与字距）📐

**① 垂直分布（Vertical Layout）**：内容块**垂直居中**，上下留白均衡，既不上顶也不下坠：

- **垂直居中**：整组内容（标题 + 正文 + 数字）的中心点落在画布**垂直中轴线附近**（建议中心 `y=48%–50%`，即内容总高占画布 `50%–60%` 时居中放置），**上下留白尽量相等**
- **上下对称留白**：内容上方留白与下方留白之差 ≤ 画布高度 `3%`（约 `40px`，以 `1080x1440` 计）；不做「重心偏下」，那会让内容堆到卡片下半部、上半部空旷
- **内容上边距**：不要从 `y=0` 顶格画；顶部留白至少 `画布 12%`，若内容较矮（总高不足画布 `50%`）则自动增大上下边距把内容撑到居中，底部不贴边
- **留白区（Padding）**：左、右 padding 均 ≥ `120px`，底部 padding ≥ `160px`；要避免卡片底部贴边被平台裁切

**② 字距与行距（Letter & Line Spacing）**：大字与相邻字挤在一起，是因为字号大但行高/字距没同步放大 🔧

- **行高（Line Height）**：正文行高 = `字号 × 1.5–1.8`；标题行高 = `字号 × 1.15–1.3`；**字号越大行高倍数越要往高取**，避免两行大字粘在一起
- **段间距（Paragraph Gap）**：标题与首段正文间距 = `字号 × 0.8–1.2`（或 ≥ 40px），段落之间 ≥ `30px`；标题、数字、正文三类元素之间强制留出**区隔空白**
- **字距（Letter Spacing）**：大字（标题 / 核心数字）字距设为 `字号 × 0.03–0.06`，中小字 `0`；字距太小会让笔画粘连
- **文字内边距（Padding around text）**：高亮数字或结论词做色块时，色块内边距 = `字号 × 0.15–0.25`，且色块与前后文字的**最小间距 ≥ 20px**，防止高亮词紧贴相邻词
- **防重叠校验**：`Pillow` 画完每行后，用 `textbbox`/`measure` 实测各行边界，若任意两行/两词的 `bbox` 纵向或横向**间距 < 8px**，则增大行高或字距后重画，不得硬挤

**③ 一行放不下的处理**：大字（尤其标题 / 核心数字）超过画布可用宽度 `90%` 时，**按词断行、增大行高**，不靠缩小字号硬塞；断行后每行仍满足字距规则 ✅

**生成方式**：用本机 Python + Pillow 绘制（解释器路径见第 2️⃣-2 节），字体 `msyh.ttc` + `consola.ttf`；也可用 Playwright 截 HTML。脚本用完即删，不在项目目录留 `.py`。⚠️ 脚本只做**排版**：文字从对应页原样读取，禁止在脚本里重写、精简或补写文案。**排版必须落地 7.1.0 细则**：内容垂直居中、上下留白均衡、字号与行距字距成比例、高亮色块与相邻文字留足间距、画完校验 `bbox` 无重叠。

### 7.3 背景音乐选曲规范 🎵

抖音图文**强制配乐**：没有 BGM 的作品完播与推荐都吃亏，且发布后无法补（见问题库第 21 条）。选曲不是凭感觉，按下面五步走。

**第一步 · 判断文档调性**：看标题与正文的「表达目的」，不是看所属技术领域。

| 文档调性 | 判定信号 | 风格方向 | 优先入口 |
|---|---|---|---|
| 知识科普 / 技术拆解 / 数据实测 | 大量数字、对照表、代码、结论型标题 | Lo-Fi Hip Hop、Chill Beats、轻音乐（纯器乐），BPM 80–90 | 推荐、热门榜，搜 `lofi` / `chill` / `纯音乐` |
| 方法论 / 效率 / 职场观点 | 清单、判断句、经验总结 | 轻快电子、Corporate、钢琴轻流行 | 推荐、流行 |
| 个人叙事 / 经历复盘 | 第一人称、时间线、故事 | 舒缓钢琴、Acoustic | 推荐 |
| 踩坑 / 反差实测 | 强对比、警示、推翻常识 | 轻节奏鼓点、Future Bass（无人声） | 热门榜、卡点（只取器乐） |

**第二步 · 联网确认风格**：对映射表选出的风格名先搜一轮，确认它是不是「纯器乐 + 情绪中性」，避免被名字误导（如「卡点」分类里大量带人声说唱）。搜索只用于定方向，最终仍回平台榜单选曲。

**第三步 · 硬指标逐条打勾**（任一条不满足就换曲）：

- **纯器乐、无歌词人声**：有人声会抢注意力，知识类作品尤其伤完播
- **BPM 80–90**，知识类不超 110；强鼓点卡点会让「冷静说理」的调性失真
- **情绪中性**：不哭腔、不悲情、不燃爆；讲「成本下降」「效率提升」却配伤感古风，属于情绪与结论打架
- **时长 ≥ 作品时长**，不足 60 秒的曲目直接跳过（图文轮播 5 张通常要 1 分钟左右）
- **优先使用人数高的曲目**：推荐 / 热门榜前列，平台分发更稳；冷门曲目可能触发版权或静音

**第四步 · 操作路径**（细节与踩坑见问题库第 19、20、22 条）：

1. 图片全部上传后，点入口真身 `span.action-Q1y01k`（父容器 `div.container-JngpiB` 点不动）
2. 面板分类：推荐 / 热门榜 / 收藏 / 飙升榜 / 原创榜 / 卡点 / 纯音乐 / 旅行 / DJ / 搞笑 / 流行 / 伤感
3. 需要搜索时，向 `input[placeholder="搜索音乐"]` 用原生 value setter 写值并派发 `input` 事件
4. 匹配到曲目后，点该行 `button.apply-btn-LUPP0D`（文案「使用」，hover 才显示）；**点行本身只切试听，不会选中**

**第五步 · 校验（唯一真值）**：发布页「扩展信息 → 选择音乐」区域变成「曲名 + 时长 + 修改音乐」。没出现这段文案就是没选中，**禁止点「发布」**。

**禁区**：强人声 / 说唱、伤感古风与哭腔、燃系卡点、带剧情音效（笑声、警报、爆炸）、与结论情绪相反的曲目。

**已发布作品无法补配乐**：网页端「编辑作品」页没有音乐模块，只能删除后重发。

### 7.4 已知失败路径 🚫

- **描述框被污染**（内容重复堆叠、计数器卡在 `1000 / 1000`）后不要原地抢救：`execCommand('delete')`、合成 `KeyboardEvent`（Ctrl+A / Ctrl+Z）、`browser_type({clear:true})` 都只改 DOM，PM 模型仍是旧文本 → 关掉该 tab、新建 tab 重开 `content/post/image`
- **「暂存离开」** 后草稿不进「内容管理」列表（该页只有「作品」tab），只能从发布页弹窗「继续编辑」恢复
- **点发布后长期停在「正在发布」** 且控制台出现 `gateway_biz_verify_with_face` → 平台要求人脸二次验证，转 `browser_waiting_for_user_interaction` 请用户过人脸，不重复重试
