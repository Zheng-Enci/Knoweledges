## 📌 适用场景

执行本 command 时，自动完成「选平台 → 读取对应 skill → 逐平台发布」全流程 🚀。
**本文件是总调度入口**，不含任何平台规则：各平台的通道要求、共用前置流程（定位/解析/封面/摘要/图片/预热）、发布步骤、问题库，已拆分到三个子 skill，按所选平台读取即可。

| 平台 | 对应子 skill | 路径 |
|------|--------------|------|
| **掘金** | `publish-juejin` | `.trae/skills/publish-juejin/SKILL.md` |
| **CSDN** | `publish-csdn` | `.trae/skills/publish-csdn/SKILL.md` |
| **抖音** | `publish-douyin` | `.trae/skills/publish-douyin/SKILL.md` |

> ⚠️ **本 command 只做调度**：不内联任何平台规则。所有发布细节（通道选择、发布步骤、问题库、前置流程、汇报模板）全部在对应子 skill 里，执行某平台前**必须先完整读取**该平台 skill。

## 0️⃣ 确认发布平台（多选，必做）

> 🔔 **本 command 唯一需要用户确认的环节**：开始发布前，用 `AskUserQuestion`（`multiSelect: true`）询问用户**本次要发布到哪些平台**，选项固定为：

| 选项 | 对应平台 | 后续动作 |
|------|----------|----------|
| 掘金 | `juejin.cn` | 读取 `publish-juejin` skill 并执行 |
| CSDN | `csdn.net` | 读取 `publish-csdn` skill 并执行 |
| 抖音 | `creator.douyin.com` | 读取 `publish-douyin` skill 并执行 |

- 💡 默认可**全选**（即默认 3 个全发），用户可自行取消；选择结果决定本轮读哪些 skill、登录哪些站点、走哪些发布步骤、汇报哪几行。
- 🔗 **平台联动**：未选中的平台在后续步骤中直接**跳过**（不读对应 skill、不登录、不发布、汇报里标注「未选」）。
- 🎯 若用户未明确多选，按**默认全选**推进，不再单独追问。

## 1️⃣ 读取并执行对应 skill

按第 0️⃣ 步所选平台，**逐个完整读取**对应子 skill，严格按 skill 内部流程执行：

1. **🏷️ 读取规则**：每个平台 skill 都是**独立完整**的——内含该平台的通道铁律、三平台共用前置流程（P1 定位 → P2 解析 → P3 封面 → P4 发布稿 → P5 摘要 → P6 图片兜底 → P7 资源预热）、平台专属发布步骤、平台问题库、全平台通用问题库、发布后汇报模板。
2. **⛓️ 执行顺序**：按「掘金 → CSDN → 抖音」顺序逐个推进；每一平台从读取 skill 开始，到发布结果上报结束，再进入下一平台。
3. **📖 独立判断**：执行某平台前，若该平台 skill 内有问题库，**先读问题库**，把命中本组内容的问题抄进临时 checklist，能先手规避的不再试错一遍。

> 🔒 **每次执行独立判断（强制清空记忆）**：执行本 command 时，**忽略本轮对话之前关于「上次发哪篇」「哪篇已发布/未发布」的所有结论与锚定**，也不要套用上一轮 agent 的口头判断。一律以**当前磁盘状态**为准（mtime 倒序 + 链接目录现状）**从零重新定位最新且未发布的一篇**。上一轮结果只作参考、不作依据。各 skill 内 P1 步骤已含定位逻辑。

## 9️⃣ 发布后汇总汇报

所有平台处理完毕后，汇总输出最终结果。**行数 = 第 0️⃣ 步所选平台数**（未选平台不出现，缺项写「未生成 / 已跳过」）：

| 平台 | 文章标题 | 专栏 / 话题 | 状态 | 链接 |
|------|----------|-------------|------|------|
| 掘金 | {母稿去编号标题} | {文件夹名或实际复用专栏} | 已发布 / 审核中 / 失败 / 未选 | {URL} |
| CSDN | {母稿去编号标题} | {文件夹名或实际复用专栏} | 已发布 / 失败 / 未选 | {URL} |

- ❌ 任一平台失败时，说明失败步骤与页面提示，**不重复盲目重试**；只允许换一条路径（换选择器、换入口）再试一次，仍失败则按「任一失败即停」终止后续平台并如实上报
- 🔁 平台已存在同名文章时，**不重复创建**，报告已有链接，并按「更新」处理（编辑原文后重新发布）
- 🧠 汇报时附「问题库更新」：本次新增 / 更新了哪个 skill 的哪些条目（无新增写「无」）
- 🧩 汇报时附「文章组清单」：2 个文件是否齐备、`source` 是否与母稿一致、所选平台各 skill 是否都已完整读取

## ⚠️ 约束

- 🚫 不修改原文档内容、不改文件名、不移动文件
- 🔒 **发布环节不改正文，三个平台一体适用**：正文必须与对应 `.md` 逐字一致；只允许排版类处理（加粗、着色 / 高亮、分页、断行、表格转图表、抖音的纯文本化）。要改文字就回文档改，改完再发
- 🚫 不自动 `git push`
- 🛑 **任一平台失败即停**：按「掘金 → CSDN → 抖音」顺序推进，某一步失败后不再发起后续平台，汇报已完成清单 + 失败步骤 + 页面提示
- 🧠 平台问题必须沉淀：遇到新 `issue` 并解决后，**立即**回写对应子 skill 的问题库；只汇报不记录视为本次任务未完成
- ✅ 发布已被用户**长期授权**：本 command 执行期间无需逐次确认，直接发布直至成功
- 🔐 唯一需要用户介入的情况：平台未登录（扫码/输密码）
