## 📌 适用场景

执行本 command 时，自动完成「找最新文档 → 清洗标题 → 生成封面图 → 处理图片 → 发布掘金 → 发布 CSDN」全流程 🚀
全程使用**内置浏览器**（browser / Chrome DevTools MCP）操作，不使用平台 API、不修改原文档 ✅

**全自动授权** 🤖：从定位文档到点击发布，全部由 AI 自主决策并执行，**不询问用户、不等待确认**，最终目标是两个平台都发布成功。遇到不确定的信息，优先参考以下来源自行判断：

1. 该账号**已发布的历史文章**（标题风格、标签、专栏归属、分类选择）
2. 平台页面上的**推荐项与提示文案**（推荐标签、已有专栏列表、字数限制）
3. **本地项目**中的目录结构、`00-xxx链接目录.md` 等既有约定

## ✅ 前置条件

1. **🕐 获取当前时间**：执行 `date "+%Y-%m-%d %H:%M"`（Git Bash）
2. **🌐 浏览器就绪**：打开浏览器，分别确认**掘金**（`https://juejin.cn`）与 **CSDN**（`https://www.csdn.net`）已登录
   - 未登录时才调用 `browser_waiting_for_user_interaction` 请用户扫码登录 🔐（登录属于唯一需要人工介入的环节）
   - 已登录则直接继续，不打扰用户

## 1️⃣ 定位最新文档

在项目根目录执行（Git Bash）：

```bash
find . -name "*.md" \
  -not -path "./.trae/*" \
  -not -path "./.git/*" \
  -not -path "./标准文档/*" \
  -not -path "*/resources/*" \
  -not -name "README.md" \
  -not -name "*url链接目录*" \
  -not -name "*目录.md" \
  -printf "%T@ %TY-%Tm-%Td %TH:%TM %p\n" \
  | sort -rn | head -n 5
```

- 🥇 取**修改时间最新**（mtime 最大）的一篇业务文档作为本次发布对象
- 📋 输出前 5 名候选及时间，向用户报告最终选中的文档及理由
- 🚫 排除项：`.trae/`、`标准文档/`、`resources/`、`README.md`、各类 `url链接目录`、临时草稿与 `.rendered.html`

## 2️⃣ 解析标题与专栏

| 字段 | 取值规则 | 示例 |
|------|----------|------|
| **专栏名** | 文档所在**文件夹名**（原样保留） | `LLM-大模型技术专栏` |
| **文章标题** | 文件名去掉扩展名 + **去掉开头编号前缀** | `LLM23-LangChain与LangGraph区别-20260929.md` → `LangChain与LangGraph区别-20260929` |

- 🔢 编号前缀正则：`^[A-Za-z]{0,4}[0-9]+[A-Za-z0-9]{0,6}[-_ ]+`
- 🧪 对照示例：
  - `J1C-IDE选择与使用-...` → `IDE选择与使用-...`
  - `09aaa-LayerNorm是什么？` → `LayerNorm是什么？`
  - `@Bean注解基础入门-...` → `@Bean注解基础入门-...`（无编号，保持不变）
  - `为什么学习Java-...` → `为什么学习Java-...`（无编号，保持不变）
- 🏷️ 标签建议：从专栏名与正文提取关键词，**掘金最多 3 个**、**CSDN 最多 5 个**（以页面提示的剩余数量为准）
- 🎯 自主决策规则：
  - 掘金标签必须从输入框下方的**候选下拉项**中选择，输入后点击匹配项；匹配不到就换相近标签，不硬造
  - CSDN 允许 Enter 键入自定义标签，优先用正文里已写明的标签
  - 分类按正文技术栈选择（Java/Spring 类选「后端」，纯数据库选「后端」，前端框架选「前端」）
  - 专栏优先复用**已存在的同系列专栏**；确实不存在时才新建，名称取文件夹名

## 2️⃣-2 🎨 生成封面图（调用 `/生成图片`）

刷信息流时用户只能看到三样东西：**标题、摘要、封面图**。标题和摘要在 2️⃣、3️⃣-2 已定，封面图必须单独造，不能拿正文首图凑数。

**做法**：调用 `/生成图片` 指令生成 **1 张**（`N = 1`），尺寸 `2560x1440`（16:9），默认不加水印；图片落盘到 `Temp/<语义化主题>_2560x1440.png`，发布时用 `upload_file` 分别上传到两平台的封面框。

**吸引力公式（按优先级）** 🔥：

1. **夸张情绪的主体**：一张脸或一个拟人化主体占画布 **15% 以上**，表情必须是夸张的惊讶、崩溃或得意——缩到 200px 时，只有极端表情还看得清。带人脸的封面实测点击率高出约 38%。
2. **眼神引流**：主体视线指向标题文字或画面冲突点，读者的眼睛会跟着走。
3. **高对比撞色**：主体与背景用互补色，优先 **黄+黑**（知识类最稳）、红+白；整体按「背景 80% 收敛、主体 20% 高饱和」分配。
4. **给结果、藏方法（悬念）**：画面只呈现冲突的结果，不给出解法——例如「三种工具被硬塞进同一层楼导致崩塌」，读者必须点进去才知道该怎么分层。
5. **文字极简**：图上最多 5-7 个字，粗黑体，字号不小于画布宽的 1/6，且不与文章标题重复。
6. **三元素上限**：主体 + 一个对比物 + 一行字，再多就糊成一团。

**必须贴合文档** 🎯：

- 视觉隐喻直接取自本文的核心冲突（如 LLM25 是「三层楼 vs 挤在一层」，S5A 是「6 张表 vs 一堆散装字段」）
- 图上文字只能来自标题或其同义改写，**禁止出现文档里没有的数字、百分比、性能指标**
- 禁止出现真实人物肖像、平台 logo、二维码、水印

**落地检查** ✅：

- 缩小到 300px 宽自查：主体、表情、那行字是否还看得清，看不清就重生成
- 两平台复用同一张，上传后确认缩略图没有裁掉主体
- 封面图与正文图片互不影响：正文图仍按第 4 节处理

## 3️⃣ 生成发布稿（不改原文档）

在临时目录生成发布副本，原文档**只读不写** 🔒

1. **✂️ 去掉正文首个一级标题**：若正文首行是 `# 与标题相同/相近的 H1`，删除该行，避免平台标题与正文标题重复
2. **🖼️ 本地图片转 GitCode Raw URL**：按 `.trae/rules/GitCode图片URL转换规范.md` 转换
   - 基础地址：`https://raw.gitcode.com/ZhengEnCi/knoweledges/raw/master/`
   - `resources/P2L/photo/xx.png` → `https://raw.gitcode.com/ZhengEnCi/knoweledges/raw/master/Python-基础技术/resources/P2L/photo/xx.png`
   - 路径统一正斜杠 `/`，中文与空格做完整 URL 编码 ⚠️
3. **🧾 正文其余内容原样保留**：不润色、不删改段落、不调整结构 🚫
4. **🧹 发布完成后删除临时发布稿**（中间产物不留存）

## 3️⃣-2 ✍️ 平台摘要撰写（必做，禁止用平台自动提取）

发布面板里的「编辑摘要」（掘金，≤100 字）与「文章摘要」（CSDN，≤256 字）**必须手动重写**，不能保留平台自动提取的内容。摘要是列表页、搜索结果与推荐流里唯一替文章说话的文案，写成正文前 100 字的复制粘贴等于放弃点击率。

**写作规则** 🔥：

1. **开头 15 字内抛痛点或反常识结论**：不用「本文介绍了」「随着……的发展」这类开场
2. **中段给具体交付物**：几张表、哪几条约束、能解决什么答辩问题；用名词和数字，不喊口号
3. **结尾留一个具体钩子**：老师最爱追问什么、哪一步最容易翻车
4. **自然嵌入 1-2 个搜索关键词**（如「学生管理系统」「数据库设计」），保证长尾搜索命中
5. **禁止**：编造数据、夸大承诺、「史上最全」「干货满满」「包过」「一键搞定」
6. **禁止直接复制正文首段**：摘要要能脱离正文独立阅读

**模板** 🧩：

```
{痛点或反常识结论}：{具体做法 + 关键数字}。{读者能拿走什么}，{留一个钩子}。
```

**示例**（本次 S5A 文档实际使用）💡：

- 掘金（≤100 字）：`答辩被追问的不是功能，而是建表语句里有没有约束。6 张表讲清学号唯一、外键级联、状态字段怎么落库，附可执行 schema.sql 与 5 个高频追问的答法。`
- CSDN（≤256 字）：`学生管理系统毕设最容易失分的地方，不是 SQL 写得不够花哨，而是约束只写在 Service 层。本文用 6 张表拆清职责边界，重点讲三件事：学号/手机号唯一约束为什么必须落进 DDL、删学生时考勤与签署记录该怎么级联、状态字段用数字还是语义字符串。附完整建表脚本与答辩高频追问的应答思路。`

**落地检查** ✅：

- 填完后读取输入框 `value`，确认字数未超限、无残留的自动摘要
- 掘金摘要框默认是 100/100 的自动内容，需**全选覆盖**
- CSDN 摘要框默认 0/256，可点「AI 提取摘要」后**再手动改写**，但不得原样提交

## 4️⃣ 图片渲染兜底（重点）⚠️

GitCode Raw 图片首次访问可能空白或返回占位图，必须验证后再发布：

1. 在浏览器**新标签页逐个打开**发布稿中的 GitCode 图片 URL
2. 等待图片真正加载完成（必要时**手动点击/刷新一次**触发 GitCode 渲染）
3. 回到编辑器，刷新预览或重新粘贴该图片，确认编辑器内**图片可见**
4. 若多次仍无法渲染：改为在编辑器中**直接上传本地图片**，替换该处外链
5. ✅ 所有图片确认可见后，才允许进入发布提交

## 4️⃣-2 🧪 配套资源链接预热（重点）⚠️

正文里的「📦 配套资源」直链（`.py` / `.java` / `.sql` / `.zip` / `.json` 等**非图片**文件）指向 `raw.gitcode.com`。该域名是 CDN，仓库文件首次被访问时可能返回 404、空白页或占位内容——只有先在浏览器里真实走到该文件、触发一次回源，raw URL 才会稳定可下载。因此发布前必须做一次「模拟人工点击」的预热，**不能直接拿未验证的 URL 去发布**。

**触发条件**：发布稿中存在 `https://raw.gitcode.com/...` 且后缀不是图片（`.png` / `.jpg` / `.jpeg` / `.gif` / `.webp` / `.svg`）的链接，或正文出现 `> 📦 配套资源：` 行。命中即必须执行，不得跳过。

**做法** 🔧：

1. **列出清单**：从发布稿中抽出全部资源 URL，逐个做 URL decode 得到仓库相对路径，整理成「URL → 相对路径」对照表
2. **进仓库首页**：`navigate_page` 打开 `https://gitcode.com/ZhengEnCi/knoweledges`，`take_snapshot` 确认页面正常渲染（不是 404、不是登录墙）
3. **模拟人工点击**：在文件树里**逐级点击**目录（如 `Transformer` → `resources` → `X01` → `code`），最后点击目标文件名进入 blob 页面
   - 必须真的点开每一级目录和文件，**不能只改地址栏直达**：本步骤的目的就是让 CDN 记录该路径的回源请求
   - 目录层级必须与正文 URL 的相对路径完全一致，大小写、中文、空格都不能改
4. **确认文件内容**：blob 页面渲染出真实源码（能看到首行代码），而不是「文件不存在」提示
5. **再点 Raw**：点击页面上的「原始数据 / Raw」按钮打开 raw 页面，确认返回的是**纯文本源码**
6. **刷新校验**：在该 raw 标签页 `navigate_page` 重新加载一次，仍能拿到内容，才算预热成功
7. **逐个复测**：对清单里每个资源 URL 重复第 2–6 步，全部通过后才允许进入发布
8. **兜底替换**：若某条 raw 链接重试 2 次仍 404 或空白，改用仓库 blob 页面 URL（`https://gitcode.com/ZhengEnCi/knoweledges/blob/master/{编码后的相对路径}`）替换正文该处链接，并在第 7️⃣ 节汇报里注明替换原因
9. **回写发布稿**：预热过程只允许调整链接形式，**不得改写资源名称、说明文字、所在段落** 🚫

**落地检查** ✅：

- [ ] 发布稿里每个资源链接都在浏览器里真实点开过，且 raw 返回纯文本源码
- [ ] 没有一条链接是「点开 404 / 空白 / 登录页」
- [ ] 正文「📦 配套资源」里的链接，与浏览器里实际打开的地址完全一致
- [ ] 若发生 blob 替换，已记录到第 7️⃣ 节汇报

## 5️⃣ 发布到掘金

1. 打开 `https://juejin.cn/editor/drafts/new?v=2`
2. 填入**文章标题**（已去编号）、**正文**（Markdown 模式粘贴）
   - 正文优先用系统剪贴板注入：`Set-Clipboard` 写入发布稿 → 聚焦 `.CodeMirror` → `Control+V`
   - 粘贴后校验 `.CodeMirror` 实例的 `getValue().length` 与发布稿字符数一致
3. 点击「发布」打开面板 → 选择**分类**、添加**标签**（最多 3 个，必须从候选下拉项点选）、上传**封面图**（用第 2️⃣-2 节生成的那张，`upload_file` 传入 `文章封面` 的上传框）
4. 选择「收录至专栏」，优先复用同名或同系列专栏
   - 不存在则新建同名专栏：创作中心 → 专栏管理 → 新建专栏，名称填文件夹名 ✅
5. **填写摘要**：按第 3️⃣-2 节撰写，覆盖默认的 100/100 自动摘要（必做，不得跳过）
6. 按第 4 节完成图片检查 → 直接点击「确定并发布」（**无需再向用户确认**）
7. 从创作者中心「文章管理」读取发布后的 URL；审核中的文章为 `/spost/` 链接，通过后自动变为 `/post/`

## 6️⃣ 发布到 CSDN

1. 打开 `https://editor.csdn.net/md/`
2. 填入**文章标题**（已去编号）、**正文**（Markdown 模式粘贴）
   - 正文区域是 `pre.editor__inner`（contenteditable），聚焦后 `Control+V` 粘贴
3. 点击「发布文章」打开面板 → 勾选**原创**，填写标签（最多 5 个，Enter 可添加自定义标签），上传**封面图**（第 2️⃣-2 节生成的那张）
4. 选择**分类专栏**：优先复用已存在的同系列专栏（例如文件夹叫 `SQL-数据库技术专栏`，平台已有 `SQL-数据库查询技术专栏` 时直接复用，避免创建近似重名专栏）
   - 确实不存在才新建：`https://mp.csdn.net/mp_blog/manage/column` → 新建专栏 ✅
5. **填写摘要**：按第 3️⃣-2 节撰写（≤256 字），不得留空、不得直接提交「AI 提取摘要」的原样结果
6. 按第 4 节完成图片检查 → 直接点击「发布文章」（**无需再向用户确认**）
7. 发布成功后 URL 形如 `https://blog.csdn.net/{user}/article/details/{articleId}`，以 `creation/success/{id}` 页面出现为准
8. 发布后抽查：Mermaid 是否渲染为 SVG（正文不应残留 `erDiagram` 源码）、标签与专栏是否落库（查 `meta[name=keywords]`）、摘要是否是改写后的版本
