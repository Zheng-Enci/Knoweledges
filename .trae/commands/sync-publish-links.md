## 📌 适用场景

文档在掘金、CSDN **发布完成后**执行本 command，自动找出**当前时间往前推 24 小时内修改过**的业务文档，逐个检查是否已写入对应专栏的 URL 链接目录，**只对尚未记录**的文档抓取线上链接，并把**审核通过**的链接归档进目录 🔗

全程使用**内置浏览器**（browser / Chrome DevTools MCP）读取平台页面，不使用平台 API、不修改原文档 ✅

> ⚠️ **CSDN 必须使用 TRAE 内置沙盒浏览器（强制）**：CSDN 内容管理后台（`mp.csdn.net`）对**未登录的隔离 profile**（chrome-devtools MCP）会触发图形验证码/风控（见发布指令问题库第 34 条），因此 CSDN 一律走本机**已登录的 TRAE Browser Control（chrome 插件）通道**（`browser_tabs` / `browser_navigate` / `browser_evaluate` 等），**禁止使用 chrome-devtools MCP**。

> ⚠️ **掘金必须使用 chrome-devtools MCP 通道（与 CSDN 相反）**：掘金内容管理页的页面读取与注入依赖 `evaluate_script` 与隔离 profile，**必须使用 chrome-devtools MCP 通道**（`chrome-devtools_navigate_page` / `chrome-devtools_evaluate_script` 等），**禁止使用 TRAE Browser Control（chrome 插件）通道**。**两套通道互斥，同一轮严禁混用**。

## ✅ 前置条件

1. **🕐 获取当前时间**：执行 `date "+%Y-%m-%d %H:%M"`（Git Bash），写入目录时取日期部分 `YYYY-MM-DD`
2. **🌐 登录状态**：确认**掘金**（`https://juejin.cn`）与 **CSDN**（`https://www.csdn.net`）均已登录
   - 未登录时调用 `browser_waiting_for_user_interaction` 请用户登录 🔐，登录后继续
3. **📋 写入前汇总**：把汇总结果（标题 / 专栏 / 平台 / 审核状态 / 待写入链接）整理成表格，**展示给用户但不等待确认**，直接写入 ✍️

## 1️⃣ 定位 24 小时内修改的文档

在项目根目录执行（Git Bash），找**当前时间往前推 24 小时内修改过**的业务文档：

```bash
find . -name "*.md" \
  -not -path "./.trae/*" \
  -not -path "./.git/*" \
  -not -path "*/resources/*" \
  -not -name "README.md" \
  -not -name "*url链接目录*" \
  -not -name "*目录.md" \
  -mtime -1 \
  -printf "%T@ %TY-%Tm-%Td %TH:%TM %p\n" \
  | sort -rn
```

- 🎯 全部命中 `-mtime -1` 的 `.md` 都是本轮同步候选，**不限一篇**，列表全部展示
- 🥇 仅用于筛选，不再「只取最新一篇」；24 小时窗口内没改过任何业务文档时，结果为 0，直接报告「无新文档」并结束
- 🚫 排除项：`.trae/`、`resources/`、`README.md`、各类 `url链接目录`、临时发布稿与 `.rendered.html`

## 1️⃣-2 🔎 剔除已记录文档（只处理未记录的）

对 1️⃣ 的每个候选文档，先查它所在专栏的 `*url链接目录*.md`（如 `LLM-大模型技术专栏/LLM00-url链接目录.md`）里**是否已记录该文档的链接**：

- **判定已记录**：`*url链接目录*.md` 中已存在该文档的**完整文件名**（含编号前缀）对应条目 → **跳过**，不进本轮抓取
- **判定未记录**：目录文件不存在、或没有该文档名条目 → 进入本轮抓取队列
- 📋 输出「候选总数 / 已记录 / 待抓取」三列明细，并列出待抓取文档清单
- 🧩 只对**待抓取**的文档执行后续 2️⃣–5️⃣ 步骤；全部已记录时报告「无需新增（All recorded）」并结束

## 2️⃣ 解析标题与专栏（遍历每个待抓取文档）

对 1️⃣-2 的**每篇待抓取文档**按下列表格解析：

| 字段 | 取值规则 | 示例 |
|------|----------|------|
| **专栏名** | 文档所在**文件夹名**（原样保留） | `LLM-大模型技术专栏` |
| **文章标题** | 文件名去掉扩展名 + **去掉开头编号前缀** | `LLM23-LangChain与LangGraph区别-20260929.md` → `LangChain与LangGraph区别-20260929` |
| **完整文件名** | 文件名去掉扩展名，保留编号 | `LLM23-LangChain与LangGraph区别-20260929` |

- 🔢 编号前缀正则：`^[A-Za-z]{0,4}[0-9]+[A-Za-z0-9]{0,6}[-_ ]+`
- 🧪 对照示例：
  - `AI05-AI生成App原型图.md` → `AI生成App原型图`
  - `09aaa-LayerNorm是什么？.md` → `LayerNorm是什么？`
  - `@Bean注解基础入门-20260801.md` → 无编号，保持不变

## 3️⃣ 掘金：抓取并校验审核状态（每个待抓取文档各跑一遍）

1. 进入掘金**创作中心 → 内容管理 → 文章列表**
   - 地址 `https://juejin.cn/creator/content/article/all`（地址失效则以页面导航为准，不编造路由 ⚠️）
2. 按**去编号标题**匹配文章（忽略首尾空格差异），匹配到多条时取**发布时间最新**的一条
3. **审核判定** ✅ / ❌：
   - 列表或详情页出现「审核中」「未通过」「审核不通过」→ **未通过校验**
   - 无上述标识且文章详情页可正常打开 → **审核通过**
4. 审核通过后取规范文章 URL：`https://juejin.cn/post/{id}`
   - `/spost/{id}` 属未过审链接，不得写入 🚫

## 4️⃣ CSDN：抓取并校验审核状态（每个待抓取文档各跑一遍）

1. 打开 CSDN 内容管理文章列表：`https://mp.csdn.net/mp_blog/manage/article`（地址失效则以页面导航为准）
2. 按**去编号标题**匹配文章，读取「**状态**」列
3. **审核判定** ✅ / ❌：
   - 状态为「已发布」→ **审核通过**（唯一通过条件）
   - 「审核中」「审核不通过」「未通过」→ 一律视为**未通过**
4. 审核通过后取文章 URL：`https://blog.csdn.net/{user}/article/details/{id}`

## 5️⃣ 写入专栏链接目录（每篇待抓取文档独立写入）

**定位**：文档所在专栏文件夹下的 `*url链接目录*.md`（如 `LLM-大模型技术专栏/LLM00-url链接目录.md`）；多篇文档可能落在不同专栏，需**逐个专栏分别定位**并写入

**先识别格式再追加** 🧩：

### 🅰️ 表格型（表头含 `| 文档名称 | 发布平台 | 链接地址 | 发布时间 |`）

在表格末行后各追加一行：

```markdown
| **LLM23-LangChain与LangGraph区别-20260929** | 掘金社区 | [LangChain与LangGraph区别-20260929 -- 掘金](https://juejin.cn/post/xxx) | 2026-10-21 |
| **LLM23-LangChain与LangGraph区别-20260929** | CSDN博客 | [LangChain与LangGraph区别-20260929 -- CSDN](https://blog.csdn.net/xxx/article/details/xxx) | 2026-10-21 |
```

- 文档名称列加粗，填**完整文件名**；掘金平台名写 `掘金社区`、链接文案后缀 `-- 掘金`
- CSDN 平台名写 `CSDN博客`、链接文案后缀 `-- CSDN`

### 🅱️ 列表型（`## 文档名` 小节 + `- [平台 - 标题](URL)`）

在该文档小节下追加：

```markdown
- [CSDN - {去编号标题}]({URL})
- [掘金 - {去编号标题}]({URL})
```

- 没有对应小节时新建 `## {完整文件名}` 小节
- 先 CSDN 后掘金，与既有条目顺序一致

### 🔁 去重与更新记录

- 链接目录中已存在同一 URL → **跳过**，汇报中注明「已存在」
- 文件含「更新记录」时追加一条：`- {YYYY-MM-DD}: 添加 "{完整文档名}" 链接（{平台}）`，两个平台都写入则合并为 `（CSDN + 掘金）`

### 🆕 链接目录不存在时

- 按文档编号前缀创建 `{编号前缀}00-url链接目录.md`（如 `LLM00-url链接目录.md`）
- 无编号前缀则创建 `00-url链接目录.md`
- 使用「标题 + 说明 + 表格 + 更新记录」标准模板，表头与第 5️⃣-A 节一致

### 🛑 专栏定位失败

平台上文章所属专栏在本地找不到同名文件夹时 → **停止写入**，报告平台专栏名，禁止猜测目录 🚫

## 6️⃣ 失败处理

| 情况 | 处理 |
|------|------|
| 某平台未找到匹配文章 | 该平台不写入，报告「未找到匹配文章」，不影响另一平台 |
| 审核中 / 未通过 | **禁止写入**，报告文章标题、平台、当前状态与建议（等待审核后重试） |
| 页面结构变化、地址失效 | 按页面导航重新定位入口，换选择器再试一次 |
| 其他失败 | 如实上报失败步骤与页面提示，不做无意义重复重试 |

## 7️⃣ 结果汇报（逐篇展示，每篇 3 行）

对 1️⃣-2 命中的**每篇待抓取文档**，各输出一组 3 行（掘金 + CSDN + 全局状态），全部文档汇成一张总表：

| 文档 | 平台 | 文章标题 | 审核状态 | 是否写入 | 链接 |
|------|------|----------|----------|----------|------|
| {完整文件名} | 掘金 | {去编号标题} | 审核通过 / 审核中 / 未通过 / 未找到 | 已写入 / 已存在 / 跳过 | {URL} |
| {完整文件名} | CSDN | {去编号标题} | 已发布 / 审核中 / 未通过 / 未找到 | 已写入 / 已存在 / 跳过 | {URL} |

- 🎯 顶部先给一行汇总：`候选 {N} 篇，已记录 {M}，待抓取 {K}，本轮写入 {W}`
- 📄 同时说明每篇写入的链接目录文件路径，以及新建目录或新建小节的情况

## ⚠️ 约束

- 🚫 只追加链接目录，不修改原文档、不改文件名、不改动既有条目
- 🚫 不编造链接、审核状态或专栏名：一律来自平台页面实际展示
- 🚫 审核未通过的文章绝不写入
- 📝 写入完成后按项目 Git 规范自动提交（commit message 用英文），**无需用户确认**；仍不自动 `git push`
