# 发布最新文档（publish-latest-doc）

> 🔒 **每次执行独立判断（强制清空记忆）**：执行本 skill 时，**忽略本轮对话之前关于「上次发哪篇」「哪篇已发布/未发布」的所有结论与锚定**，也不要套用上一轮 agent 的口头判断。一律以**当前磁盘状态**为准（mtime 倒序 + 链接目录现状）**从零重新定位最新且未发布的一篇**。上一轮结果只作参考、不作依据。

> 📄 **完整规范参考**：本 skill 的详尽操作步骤、平台问题库、图片生成参数、选曲规范、错误处理全部以 [publish-latest-doc.md](../../commands/publish-latest-doc.md)（本仓库 command 文件）为准。本文件作为入口与兜底检查清单，执行时先读该 command 文件，再按步骤执行。

## 目标

把知识库「最新一篇文章组」（母稿 + 抖音变体）分发到 **掘金 + CSDN + 抖音** 三个平台位，全部发布成功。**CSDN 不跳过，必须发布**。

> ⚠️ **CSDN 必须使用内置浏览器通道**：CSDN 编辑器对**未登录的隔离 profile**（chrome-devtools MCP）会触发图形验证码/风控（见问题库第 34 条），因此 CSDN 一律走本机已登录的 TRAE Browser Control（chrome 插件）通道（`browser_tabs` / `browser_navigate` / `browser_evaluate` / `browser_upload_file` 等），**禁止使用 chrome-devtools MCP**。

## 前置条件检查（先读 command 文件）

1. **先读问题库**：通读 command 文件第 8️⃣ 节「平台问题库」，把命中本组变体的问题抄进临时 checklist。
2. **获取当前时间**：`date "+%Y-%m-%d %H:%M"`。
3. **浏览器就绪**：依次确认 3 个站点已登录——掘金 `https://juejin.cn`、CSDN `https://www.csdn.net`、抖音 `https://creator.douyin.com`；未登录才调用 `browser_waiting_for_user_interaction` 请用户扫码。⚠️ CSDN 必须使用本机已登录的 TRAE Browser Control（chrome 插件）通道，禁止 chrome-devtools MCP。
4. **变体齐备**：`-抖音.md` 存在且 front-matter 完整。

## 执行主流程

- **① 定位文章组**：按 command 第 1️⃣ 节 `find` 命令取母稿 mtime 最新一篇，推导变体路径；但 `find` 只按 mtime 倒序、**不判断是否已发布**，必须再叠加「**最新且未发布**」过滤——逐篇检查对应专栏 `00-*链接目录.md`，标题已在链接目录出现（任一平台）即视为已发布，跳过；取 mtime 最新且未发布的一篇。
- **② 解析标题/专栏/front-matter**：按第 2️⃣ 节，串台校验变体 `source` 必须等于母稿完整文件名。
- **③ 生成封面图**：按第 2️⃣-2 节，横版 2560x1440（掘金）+ 竖版 **3:4 `1080x1440`**（抖音卡片，`P01` 兼封面），用 `.trae/commands/生成图片.md` 或本机 Python + Pillow。
- **④ 生成发布稿**：按第 3️⃣ 节，剥离 front-matter、去首个 H1、本地图片转 GitCode Raw URL；抖音额外做纯文本化。
- **⑤ 平台摘要**：按第 3️⃣-2 节，掘金 ≤100 字、变体用 front-matter `summary` 压缩。
- **⑥ 图片/资源预热**：按第 4️⃣ 节与 4️⃣-2 节，验证 GitCode 图片与配套资源 Raw URL 可访问。
- **⑦ 发布掘金**（母稿）：按第 5️⃣ 节。
- **⑧ 发布 CSDN**（母稿）：按第 6️⃣ 节，**必须使用内置浏览器通道**（TRAE Browser Control / chrome 插件通道），禁止 chrome-devtools MCP。
- **⑨ 发布抖音**（变体）：按第 7️⃣ 节，正文一页一卡转 **3:4 `1080x1440`** 卡片图，标题 ≤20 字、描述 ≤200 字 + 话题、**必须选背景音乐**；卡片遵守 7.1.0 卡内排版与右侧安全区。
- **⑩ 发布后置顶评论**：按 7.2.1 节，用作者账号在作品下**置顶一条钩子评论**（补新角度 + A/B 选项 + 一句引导），作为第二道钩子；24 小时内回复新评论。
- **⑪ 发布后汇报 + 更新问题库 + git**：按第 9️⃣ 节表格汇报；新踩的坑立即写入问题库；所有 git add/commit 自动执行，禁止 push。

## 卡片排版铁律（第 7️⃣ 节）

- 📐 **尺寸统一**：全部卡片 `1080x1440`（3:4 竖版），禁止混用其它比例。
- 🎨 **全组统一色板**：深底 `#0B0D12` + 浅字，强调色统一高饱和绿 `#22C55E`（竖条/表头/进度条/关键数字/结论），亮黄 `#FFD400` 仅作单个数字或色块点缀；**封面 `P01` 与正文必须共用这板，禁止封面单独另起色系**。**高亮色语义全组固定**：数字类（占比/倍数/耗时）统一亮黄，结论/判断词统一强调绿，同类词禁止在不同页用不同颜色。
- 🧱 **视觉骨架（必做）**：每条 bullet 前加序号 `①②③` 或绿色实心点 + 竖线，重点页用分组色块/进度条/数据块承载核心数字，并列对齐、递进用 `→`；**禁止一条条平铺的碎片字漂浮在画布上**。
- 📐 **内容密度**：正文 + 标题总高占画布 **≥55%**（目标 60%–75%）；不足则先放大字号/行高/段距把主体撑满再居中，**不得让下半片大片留黑**。
- 📐 **7.1.0 卡内排版**：上下留白之差 ≤ 画布高 `3%`（约 40px），不做重心偏下；行高按字号成比例（正文 ×1.5–1.8、标题 ×1.15–1.3）、段距 ≥30px、大字字距 ×0.03–0.06；用 `textbbox`/`measure` 实测任意行/词间距 <8px 就加大重画。
- 🖼️ **右侧安全区**：抖音 feed 右侧约 **1/7** 被头像/点赞/评论遮挡，右侧留白 ≥ 画布宽 `15%`（约 160px），核心文案整体左移，标题/数字/色块不得进入右侧遮挡区。
- 📏 **文字测宽铁律（封面/卡片脚本必守）**：禁止固定 `(x,y)` + 固定字号放文字；必须先 `textlength`/`textbbox` 测量再定字号与起点，用 `fit_font(text, max_w, start_size, max_size)` 递归缩放至宽度 ≤ `max_w`，保证任何文本不超出画布右缘；起点避开左侧主视觉并反算 `right_max_w = 画布宽 - right_x - 右侧安全边距`。落地脚本后跑一次确认无溢出再 `upload_file`。
- ✅ **7.1.1 封面专项自检**：撞色对比强调色必须与全组一致（深底 + 绿），黄色只可点缀不可整卡另起。

## 关键铁律（不可省略）

- 🔒 **正文零改动**：发布提交的正文必须与对应 `.md` 逐字一致，只做排版类处理（加粗/着色/分页/断行/表格转图/抖音纯文本化）。要改文字回文档改。
- 🎵 **抖音必须配背景音乐 + 风格硬拦截**：未选中曲目禁止点「发布」；且选曲**只允许从「推荐 / 热门榜 / 纯音乐」三类取**，禁止进入「伤感 / 流行 / DJ / 搞笑」分类。含哭腔、悲情、伤感古风、燃爆、强人声的曲目一律禁用；选完以「曲名 + 时长 + 风格方向」复核与文档调性一致（知识类默认「冷静说理」，配伤感属情绪错配）。**点「发布」前必须用 `browser_evaluate` 校验发布页出现「曲名 + 时长 + 修改音乐」文案**，未出现即未选曲，禁止点发布，返回第 6 步重新选曲。
- 🛑 **任一平台失败即停**：按「掘金 → CSDN → 抖音」顺序，失败后不再发起后续平台，如实上报。
- 🧠 **问题必须回写**：遇到新 issue 并解决后立即更新 command 第 8️⃣ 节问题库；只汇报不记录视为未完成。
- ⚠️ **MCP workspace roots 限制**（问题库第 33 条）：要上传的封面/卡片图先复制到 `C:\Users\zheng\AppData\Local\Temp\`，再 `upload_file` 该绝对路径；`evaluate_script` 脚本用 `function` 参数内联。
