# 文档生成（generate-doc）

> 📄 **完整规范参考**：本 skill 的全文流程、平台变体规则、关键词高亮、互动钩子、硬约束全部以 [generate-doc.md](../../commands/generate-doc.md)（本仓库 command 文件）为准。本文件作为入口与铁律兜底，执行时先读该 command 文件，再按步骤执行。

## 目标

按 `.trae/rules/文档写作铁律.md`（P0）与 `.trae/rules/system-prompt.md` 生成一篇技术文档，**一次固定产出 2 个 `.md`**：母稿（CSDN + 掘金共稿）+ 抖音变体。

## 前置条件

1. 读 `generate-doc.md` command 文件全文。
2. 读 `.trae/rules/文档写作铁律.md`（P0）、`system-prompt.md`、`联网搜索与参考链接规范.md`。
3. 确认选题所属专栏与编号：先 `Glob` 专栏目录里最大编号，顺延一个；若无重复主题则独占新编号。

## 执行主流程

- **① 全局规划**：联网搜索选题，生成完整目录（仅标题大纲），提炼 3–5 个长尾关键词定文件名与 H1。
- **② 逐章填充**：一次只处理一个章节，先搜该章节主题再写内容，完成后进下一章。
- **③ 全局连贯**：每补一章回到全文，统一术语、衔接逻辑、避免重复，并回指前序文章（系列首篇除外）。
- **④ 产出结构**：母稿无 front-matter + 目录（纯文本不可跳转）等 10 章左右；抖音变体带 front-matter（platform/title/summary/tags/limits/source），正文按 `P01…PN` 分页（6–18 页），不放外链与代码块。
- **⑤ 自查**：按 T1–T10、E1–E5、第 9 节 9.5 清单逐条核对。

## 关键铁律（不可省略）

- 🔒 **一次只产 2 个文件**：母稿 + 抖音变体；母稿不加 front-matter，变体必须加。
- 🎯 **抖音分页骨架**：`P01` 兼封面（标题 + 核心数字 + 可选页脚），末页给判据式结论 + 一句互动钩子；页序固定不可增删。**每页标题必须写成「结论句/观点短语」**（如「算力永远追不上需求」），禁止只用名词；**每条 bullet 必须是『自解释完整句』**（含主语或语境，单看一条就能看懂），禁止电报体碎片、禁止跨行腰斩句意、禁止把一句话拆成两条。
- 🔑 **关键词高亮**：用 `**…**` 包裹，每页 2–4 处，按数字/术语/结论三类选词，**实际着色不超过 2 种**（数字类统一亮黄 `#FFD400`、结论类统一强调绿 `#22C55E`），同类词全组固定同色，禁止此页绿、彼页黄；P01 标题与核心数字必标，末页结论必标。
- 🪝 **互动钩子**：正文末尾 + 末页各一句，都须满足「具体经历 + A/B 选项 + 一句话能回 + 轻微争议 + 呼应标题」5 点。
- 🚫 **执行期间禁止提问**：遇到模糊需求按决策规则自行决定，不调用 AskUserQuestion 等确认类工具。
- 🔒 **数据一致**：变体里的数字必须与母稿逐项一致，不得新造；母稿超篇幅只压成一篇，不拆篇、不询问。
- 🏗️ **文件名规范**：禁止 `xxx-2.md`、`xxx（修订版）.md`；历史 `-知乎/-小红书/-腾讯云` 不再生成。

## 交付汇报

完成后输出两文件的路径（母稿 + 变体）与核心结论，并按 Git 规范逐文件提交（不 push）。
