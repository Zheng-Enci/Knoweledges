# 回复评论（reply-comment）

> 👉 **触发方式**：可由用户说「回复评论 / 回评论 / reply comment」等关键词**独立触发**。本 skill 与发布 skill 解耦——发布时由 `publish-*` 负责「发布即评论」，本 skill 专门处理对**既有评论**的回复。

## 🎯 通用流程（跨平台）

回复任意平台评论，统一走五步：

1. **定位评论**：进该平台的通知中心或作品详情页，找到目标评论。通知中心 URL 若平台有坑，按对应平台章节的地址走。
2. **精准截取评论区**：用**平台专属 selector** 定向定位评论区容器，不要用 `interactive-only` 快照全量截取（会漏掉回复按钮、混入同名干扰按钮）。
3. **展开回复输入框**：目标评论下方有「回复」入口按钮，先点开再输入——回复框常是 `contenteditable` div（非 `textarea`），点开后才出现「取消回复」+「回复」按钮。
4. **输入回复**：按「回复文案规范」组织文案（接梗、不写废话），写入回复框。
5. **提交并确认**：点「回复」提交后，**以 DOM 状态为准**确认成功（评论计数 +1、出现带作者标识的回复），不是只看按钮被点了。

## 📌 平台经验

### 掘金（已沉淀）

**① 通知中心 URL 有坑** 🔍

- 评论消息页的正确地址是 `https://juejin.cn/notification`（**单数**）。
- 写成 `/notifications`（复数）会被**重定向回首页**，白跑一趟。进通知中心一律用单数路径。

**② 评论区定位用 selector 精准命中** 📌

- `interactive-only` 快照会把每条评论下的「评论」回复按钮（class `action-reply`）**过滤掉**，还会**混入**「相关推荐」卡片里的同名「评论」按钮。
- 改用 `selector: .jj-comment-list-container` 定向截取，一次精准拿到目标评论，避免误点相关推荐的同名按钮。

**③ 回复交互流程** 🔄

- 每条评论下方有个「评论」按钮（实为**回复入口**）。
- 点击后才展开回复输入框（`contenteditable` div，**不是 textarea**），并出现「取消回复」+「回复」按钮。
- 顺序固定：先点开 → 再输入 → 再提交。

**④ 确认发布成功看 DOM 状态** ✅

- 提交后评论区计数从「评论 1」变「评论 2」，并出现你的作者回复（带「作者」标识），才算真成功。
- 不能只看「回复」按钮被点了。

**⑤ 回复文案规范** ✍️

- **别写「细节可以看文章正文」这类话** 🔪：评论者都是读完文章才来评论，写这句等于废话，反而显得没接住对方的梗。
- 回复要**顺着对方的比喻 / 语气接下去**：例如对方玩「铸造 vs 3D 打印」的梗，就顺着夸他比喻贴切并延伸一层，比干巴巴的答谢更能建立互动。

**⑥ 点赞作「已回复」标记** 👍

- **回复入口就在 `https://juejin.cn/notification`**：进入该页即可对评论做回复，点「回复」展开输入框直接回。
- **每条回复完必须顺手点个赞** 🔒：回复提交成功（按④判据确认）后，立即给那条评论点赞。
- **点赞 = 已回复的标记**：下次再来回复时，**先筛选没点赞的评论**——没点赞 = 上次没回复到的，优先处理；已点赞的视为已回复，跳过。**判断「已点赞」看点赞按钮是否带 `active` class**：已点赞的按钮显示 `active`，未点赞的没有，用这个 DOM 状态一眼区分哪些已经回过了。
- **点赞只能在 `https://juejin.cn/notification` 完成** ⛔：不在作品详情页或其它入口点赞，统一收敛到通知中心这一处，保证标记一致、不遗漏。

### CSDN（已沉淀）

**① 评论回复页面固定** 💬

- CSDN 评论回复统一在 `https://mp.csdn.net/mp_blog/manage/comment`（内容管理 → 评论）完成。
- 该页即可回复，且**每条评论的「是否已回复」状态在这页直接可见**——一眼看出哪些还没回。
- **所有操作都在这个页面**：回复、查看已回复与否，全部在此页完成，不在作品详情页等其它入口操作。

## 🔒 硬约束

- **通道复用对应平台发布通道**：掘金走 chrome-devtools MCP；抖音/CSDN 按对应 publish skill 的通道铁律执行，两套通道互斥、严禁混用。
- **文案不敷衍**：回复必须接梗、有信息增量，禁止「看正文」「谢谢支持」这类零信息回复。
- **确认靠 DOM 状态**：提交后必须核实计数与作者标识，未确认成功不得当作已完成。
